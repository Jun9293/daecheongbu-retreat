# 대청부 수련회 총무팀 통합 관리 시스템

수련회 **일정 · 할 일 · 예산**을 한 곳에서 관리하는 모바일 우선 웹앱입니다.
설계 배경은 [CLAUDE.md](CLAUDE.md)와 [docs/설계문서_v1.md](docs/설계문서_v1.md)를 참고하세요.

현재 상태: **Phase 2 완료 + 실제 2026 여름수련회 Belong 데이터 반영**

---

## 실행 방법

### 가장 쉬운 방법 (Windows)

`run.bat` 파일을 더블클릭하세요. 처음 실행하면 필요한 것들을 자동으로 설치합니다.
검은 창이 뜨면서 아래 주소가 보이면 성공입니다.

    http://127.0.0.1:8000

### 직접 명령어로 실행

```bash
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe seed.py          # 데모 데이터 (처음 한 번만, 선택)
.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### 휴대폰에서 접속하기

PC와 휴대폰이 **같은 와이파이**에 있으면, PC의 IP 주소로 접속할 수 있습니다.

```bash
ipconfig
```

여기서 나온 IPv4 주소로 `http://192.168.0.x:8000` 처럼 접속하세요.
브라우저 메뉴에서 **홈 화면에 추가**를 누르면 앱처럼 쓸 수 있습니다(PWA).

## 식대 정산 규칙

기존 "Belong 예산.xlsx"에서 실측 검증한 공식을 그대로 구현했습니다.

```
지원금액   = min(영수증 금액, 인원수 × 1인당 상한)
개인부담액 = 영수증 금액 - 지원금액
```

- **1인당 상한은 하드코딩하지 않고 회차별 설정값**입니다 (`설정 > 회차 설정`).
  여름수련회 8,000원, 소그룹지원비 규정 5,000~7,000원 등 규정에 맞춰 바꿔 쓰면 됩니다.
- 예산 집행액에는 **지원금액만** 반영됩니다. 초과분은 개인부담이므로 수련회 예산에서 나가지 않습니다.
- 기존에 비고 칸에 "9명 박민준 홍성헌…"처럼 적던 인원수·명단은 전용 입력칸으로 분리했습니다.
- 같은 부서가 "모임 식사비-1, -2, -3…"으로 반복 등록하는 흐름을 고려해, 직전 입력값
  (부서·결제자·계좌·참석자 명단)과 다음 항목명이 자동으로 채워집니다.

## 안전망 (Phase 2)

담당자가 놓쳐도 시스템이 대신 알아차리게 하는 부분입니다.

**선후행 의존성**
- 할 일에 "먼저 끝나야 하는 작업"을 지정하면 후행은 ⛔ 로 막힌 상태가 됩니다.
- 선행이 완료되면 후행이 ▶ **시작 가능**으로 자동 전환되고, 후행 담당자와 그 부서에 알림이 갑니다.
- 서로를 기다리는 순환 관계는 등록 단계에서 거부됩니다.

**자동 위험 점검** (1시간마다 자동 실행, `더보기 > 지금 위험 점검하기`로 수동 실행)
| 상황 | 알림 대상 |
|---|---|
| 기한이 지남 | 담당자 + 부서 + **총무팀** (상태도 자동으로 '지연'으로 전환) |
| 마감 D-3 / D-1 / 당일 | 담당자 + 부서 |
| 담당자 없이 마감 7일 이내 | 담당자 + 부서 + **총무팀** |
| 선행 작업이 지연됨 | 후행 담당자 + **총무팀** |

같은 상황으로 매일 중복 알림이 오지 않도록 중복 방지 키가 걸려 있고, 날짜가 바뀌면 다시 알립니다.
**열람 전용 계정에는 알림이 가지 않습니다.**

**부서 간 확인 요청**
- 할 일이나 파일에 대해 관련 부서에 "확인 요청"을 보내면 그 부서원에게 알림이 갑니다.
- 요청받은 부서만 승인/반려할 수 있고, 코멘트와 함께 요청자에게 결과가 통보됩니다.
- 파일에 대한 요청이 승인되면 파일 상태도 자동으로 '승인'이 됩니다.

**작업 파일**
- 새 버전을 올리면 v1, v2… 로 이력이 쌓이고 예전 버전도 계속 내려받을 수 있습니다.
- 승인된 파일에 새 버전을 올리면 상태가 다시 '작업중'으로 돌아갑니다 (예전 승인이 새 파일에 잘못 적용되지 않게).

**회의록 → 할 일**
- 액션아이템에 담당자·기한을 적고 "할 일로 등록"을 누르면 그대로 Task가 되고 담당자에게 알림이 갑니다.
- 같은 항목을 두 번 등록하지는 않습니다.
- 수련회와 무관한 일반 회의도 "연결 안 함"으로 기록할 수 있습니다.

### 웹 푸시 알림에 대해

`알림함` 화면에서 **알림 켜기**를 누르면 브라우저 푸시를 받습니다. 다만 웹 푸시는
브라우저 규격상 **HTTPS 또는 localhost 접속에서만** 동작합니다.
같은 와이파이에서 `http://192.168.x.x:8000` 으로 접속한 휴대폰에서는 켤 수 없고,
운영 배포에 HTTPS를 붙이면 해결됩니다.

**푸시를 켜지 않아도 알림은 항상 앱 알림함에 쌓입니다.** 푸시 발송이 실패해도
알림 자체는 남으므로, 알림 하나가 시스템의 단일 실패점이 되지 않습니다.

VAPID 키는 첫 실행 시 `data/vapid_private.pem` 에 자동 생성됩니다 (git 제외).
이 파일을 지우면 기존 구독이 모두 무효가 되니 옮길 때 함께 가져가야 합니다.

## 운영 배포 전에 해야 할 일

1. **SMS 벤더 연동** — 현재는 개발 모드라 인증번호가 화면에 표시됩니다.
   `app/sms.py`에 벤더 Provider를 추가하고 `DCB_SMS_PROVIDER` 환경변수를 바꾸면 됩니다.
   추천 순서: Solapi(가입 즉시 사용, 건당 ~20원) → NHN Cloud SMS → 알리고.
   어느 벤더든 **발신번호 사전등록**(통신사 규제)이 필요합니다.
2. **`DCB_SECRET_KEY` 설정** — 세션 쿠키 서명 키. 기본값은 개발용이라 반드시 바꿔야 합니다.
3. **`DCB_DEV_MODE=0`** — 인증번호가 화면에 노출되지 않게 합니다.
4. **DB 이전** — 여러 명이 동시에 쓰는 운영 환경에서는 SQLite 대신 PostgreSQL을 권장합니다.
   `DCB_DATABASE_URL`만 바꾸면 됩니다 (`postgresql+psycopg://...`).
5. **호스팅** — Railway / Render / Fly.io 중 하나를 권합니다(파일 업로드용 디스크가 필요).
   Vercel은 서버리스라 SQLite·업로드 파일 저장에 맞지 않습니다.

### 환경변수

| 이름 | 기본값 | 설명 |
|---|---|---|
| `DCB_DATABASE_URL` | `sqlite:///data/app.db` | DB 연결 문자열 |
| `DCB_DATA_DIR` | `./data` | DB·업로드 파일 저장 위치 |
| `DCB_SECRET_KEY` | (개발용 값) | 세션 쿠키 서명 키 — **운영 시 필수 변경** |
| `DCB_SMS_PROVIDER` | `console` | `console`이면 서버 로그로만 발송 |
| `DCB_DEV_MODE` | `1` | `1`이면 인증번호를 화면에 표시 |
| `DCB_PUSH_CONTACT` | `mailto:admin@example.com` | 웹 푸시 VAPID 연락처 — 운영 시 실제 주소로 변경 |
| `DCB_RISK_SCAN_INTERVAL` | `3600` | 자동 위험 점검 주기(초). `0`이면 자동 점검 끔 |
| `DCB_MAX_ASSET_MB` | `50` | 작업 파일 업로드 최대 크기(MB) |
