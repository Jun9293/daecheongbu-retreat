## 1. 한 문단 요약

대학청년부 수련회를 준비·진행·정산하는 웹 시스템입니다. 담당 전도사와 총무팀장이 매 회차 바뀌어도
구멍이 생기지 않게 하는 것이 목적입니다. FastAPI + SQLAlchemy + Jinja + SQLite 로 만들었고,
링크 하나로 접속하는 반응형 웹앱입니다. Phase 1 에서 **로그인·권한 / 새 회차 세팅 마법사 /
준비 단계 보드 / 팀별 업무 수집** 을 완성했습니다. Phase 2(진단 패널·수련회 진행 화면·웹 푸시)와
Phase 3(재정·회의록·STT)은 아직입니다. **진단 패널은 코드에 한 줄도 없습니다** — 검색 결과 0건으로
확인했습니다.

## 2. Phase 1 에서 내린 가장 중요한 구조 결정

### 업무를 회차에서 떼어냈습니다

```
TaskLibrary (영속)  ──<  TaskRun  >──  Retreat (회차)
   업무의 정의            실행 기록          회차
```

업무는 라이브러리에 영구히 남고, 회차는 "그중 무엇을 실행했는지"만 기록합니다.
이번 회차에 빼도 **삭제되지 않고 `included=false` 로 남습니다.**
그 기록이 다음 회차 자동 분류(필수·추천·후순위)의 입력값이 됩니다.

이게 이 시스템의 중심입니다. "아무것도 삭제하지 않는다"는 원칙이 데이터 모델 자체로 구현된 것입니다.

### 라이브러리는 절대 날짜를 갖지 않습니다

네 개의 값만 저장하고, 회차의 개회일로 매번 다시 계산합니다.

| 필드 | 뜻 |
|---|---|
| `date_anchor` | `week`(D-주차 일요일 기준) 또는 `open`(개회일 기준) |
| `default_d_week` | D-몇 주차인지 |
| `default_offset_days` | 그 주 일요일로부터 며칠째인지 (0~6) |
| `default_span_days` | 며칠짜리인지 |

**요일 오프셋을 따로 둔 이유**가 중요합니다. 개회일 요일이 회차마다 달라도
(2026 여름은 금요일 개회, 2027 겨울은 금요일 개회지만 언제든 달라질 수 있음)
업무가 걸린 요일이 유지되어야 하기 때문입니다. 봉사자들이 주말에만 모이므로 요일이 실제 제약입니다.

계산식은 `app/domain/dweek.py` 에 있습니다.

```
D-1주차 = 개회일 직전 일요일   (개회일이 일요일이면 그 전주 일요일)
D-N주차 = D-1주차 - (N-1) × 7일
```

### 준비 단계 보드 `/` `/board` — 새로 만든 것

`docs/mockups/retreat-board-v4.html` 을 그대로 구현했습니다.

- **가로축** — D-13주~D-3주는 주 단위 11칸, D-2주부터 개회일 전날까지 하루 단위 12칸,
  마지막에 수련회 기간 1칸. 총 24칸. 단위가 바뀌는 지점에 굵은 세로선.
- **세로축** — 부서 → Main → 하위 트리. 부서 헤더를 눌러 접고 펼침.
- **상태 4종** — 예정(흰 바탕+팀색 테두리) / 진행중(팀색 20% 농도) / 완료(회색) / 지연(붉은색+배지).
  **완료를 일부러 눈에 띄지 않게** 했습니다. 목적이 구멍 방지라면 시선은 미완료로 가야 하므로,
  일반적인 간트와 반대 방향입니다.
- **관련업무 고스트** — 담당팀이 아니어도 결과물을 받아야 하는 팀 행에 점선 바로 나타납니다.
- **연결 강조** — 업무를 클릭하면 관련 업무로 파란 점선 곡선이 이어집니다.
- **날짜 필터** — 상단 날짜 칸을 클릭하면 그 날짜가 기간에 포함된 업무만 남습니다.
- **바를 끌어 날짜 옮기기** — 좌우로만. 칸에 물려 떨어지고 기간은 유지됩니다. 주 단위 칸에 놓을 때는
  원래 요일을 지켜 그 주 안에 놓습니다. 바뀌는 것은 `TaskRun` 뿐이고 라이브러리의 기본 D-주차는
  그대로입니다 — 한 회차에서 당겼다고 다음 회차 기준까지 따라 움직이면 안 되기 때문입니다.
  내 부서 업무만, 고스트 바는 원본에서만.
- **상세 패널** — 오른쪽에서 열리고 본문이 밀립니다(보드가 가려지지 않음). 왼쪽 가장자리를 드래그해 폭 조절.
  탭 4개: **업무 규칙** / 논의 내역 / 달력 / 연결된 업무. 열면 업무 규칙이 먼저 보입니다.
  기간·담당팀·담당자를 여기서 바로 고칩니다. 편집 칸은 평소 글자처럼 보이고 마우스를 올려야
  테두리가 나옵니다 — 상시 입력처럼 보이면 읽기 위한 패널이 입력 폼으로 읽힙니다.
- **업무 규칙** — 이 업무를 *어떻게 진행하는지*. 논의가 이번 회차의 사정이라면 규칙은 매번 같은
  방식으로 하기 위한 것이라, 회차가 아니라 **라이브러리(`TaskLibrary.rules`)에 붙습니다.**
  담당자가 바뀌어도 "이건 이렇게 한다"가 사람이 아니라 기록에 남는 자리입니다.
- **논의 내역** — 기존 기록을 지우지 않고 취소선을 긋고 아래에 새 내용을 붙입니다(노션에서 쓰던 관례).
  회차를 넘어 따라오며, 지난 회차 것은 접힌 상태로 보입니다.
  **말을 바꾸는 것과 잘못 쓴 것을 고치는 것은 다릅니다** — 결정이 뒤집힌 것은 취소선 + 후속 기록,
  오타·오기는 그 자리에서 수정. 자기가 쓴 것만, 총무팀은 전부. 지난 회차에서 따라온 것은 손대지 않습니다.
  날짜·작성자는 본문 위 한 줄에 두고 본문은 그 아래 왼쪽 끝에서 시작합니다 — 날짜 옆에서 시작하면
  번호 매긴 목록의 첫 줄만 밀려 어긋납니다.
- **입력칸은 노션처럼** — `1.` 뒤 엔터에 다음 번호가 붙고, 빈 항목에서 엔터를 치면 목록을 빠져나옵니다.
  `-` + 스페이스로 글머리표(`•`), 탭으로 한 단계 안(`◦` → `▪`), 시프트+탭으로 밖.
  줄바꿈은 저장 후에도 그대로 보입니다. 업무 규칙 입력칸도 같습니다.
- **바 라벨** — 바보다 길면 잘리지 않고 밖으로 흘러나갑니다. 같은 글자를 두 겹으로 깔고
  바 경계에서 잘라 이어붙입니다(폭은 캔버스 `measureText`, 글꼴 로딩 후 재계산).
- **권한** — 부서 리더는 자기 부서만 펼쳐지고 나머지는 **0.78 투명도로 흐리게**(숨기지 않음).
  다른 부서 업무는 볼 수는 있지만 상태·논의는 고칠 수 없습니다(403).
- **모바일** — 820px 아래에서는 24칸 간트 대신 **D-주차 → 부서** 순 목록으로 바뀝니다.
  "이번 주에 뭐가 있나"가 먼저 보여야 하므로 주차가 바깥 묶음입니다.

### 새 회차 만들기 `/setup` — 새로 만든 것 (총무팀 관리자 전용)

`docs/mockups/retreat-setup.html` 을 그대로 구현했습니다. 4단계 마법사입니다.

1. **회차 정보** — 개회일을 넣으면 D-주차가 즉시 다시 계산되고 명절 충돌이 표시됩니다.
2. **부서 확정** — 눌러서 제외하거나 **새 부서를 추가**합니다. 새 부서에는 서버가 회차를 넘어 쓸
   키(`team1`, `team2` …)를 발급합니다 — 한글 이름으로는 안전한 키를 만들 수 없고, 그 키가
   다음 회차에서도 같은 부서임을 알아보는 유일한 근거입니다. 여기서 **각 팀에 업무 선택 요청**을
   보낼 수도 있습니다(아래 `/draft`).
3. **업무 라이브러리** — 구조가 보이게 놓았습니다. `Main 업무` / `일정` / `Claude 제안` 을 가르고,
   진행 순서(시작일 순)로 정렬하고, 시작 주차가 바뀌는 곳에 D-주차 눈금을 둡니다. Main 아래에
   하위 업무를 들여쓰기로 보여주고, 상위를 끄면 하위도 함께 흐려집니다. 상위 업무는 가나다순 +
   이름으로 좁혀 찾기. 기간은 보드와 같은 눈금(주 단위 → 일 단위 → 수련회 칸)으로 고르고
   **D-26주**까지 열려 있습니다. 여기서 **업무를 새로 만들거나 고칠 수 있습니다** —
   라이브러리를 고쳐도 지난 회차의 실행 기록 날짜는 건드리지 않습니다.
4. **확인 및 생성** — 요약 + 구멍 방지 경고.

**자동 분류**는 사람이 지정하지 않고 실행 이력에서 계산하되, **쌓인 회차 수를 넘어서는 말을
하지 않습니다** (5장 참고). 3단계에 분류 근거가 몇 회차인지 함께 표시됩니다.

**구멍 방지 경고 4종**이 4단계에서 뜹니다 — 빠뜨리면 안 될 업무 누락(수동 지정 또는 이력 근거,
각 줄에 근거를 함께 표시) / 제외한 부서가 맡던 업무에 담당 없음 / 명절 주간 배정 /
미실행으로 기록될 건수.

### 업무 라이브러리 `/library` — 새로 만든 것 (총무팀 관리자 전용)

회차를 넘어 남는 업무 목록에서 **필수**를 손으로 지정합니다. 이력이 얕은 동안 구멍 방지를
맡는 장치이며, 이력이 쌓인 뒤에도 자동 분류와 함께 유효합니다.

### 팀별 업무 수집 `/draft` — 새로 만든 것

마법사 2단계에서 요청을 보내면 회차 정보와 부서만 정해진 **초안**이 열리고 부서마다 칸이
하나씩 생깁니다. 부서 리더는 자기 칸만, 총무팀은 전부 봅니다. **임시저장**은 몇 번이든,
**제출**은 "우리 팀은 다 골랐다"는 표시입니다. 마법사 3단계는 **제출된 것만** 모으고,
제출하지 않은 팀이 있으면 "지금 만들면 그 팀의 업무는 빠집니다"라고 알립니다.
초안은 한 번에 하나만 엽니다 — 두 개가 열려 있으면 팀이 어느 쪽을 채울지 모릅니다.

### 회차 개설 후 업무 추가 `/board/add` — 새로 만든 것

라이브러리에 있는 것을 넣거나 새로 만듭니다. 새로 만든 것도 라이브러리에 남아 다음 회차
후보가 됩니다. 미실행으로 기록돼 있던 업무를 다시 넣으면 그 기록이 되살아납니다.

### 기존 화면 (이전 설계, 재설계 대상)

`회의록`(`/meetings`) · `수련회 진행`(`/schedule`) · `재정`(`/budget` `/expenses` `/refunds`) 탭은
**이전 설계에서 만든 화면으로 연결되어 있습니다.** 동작은 하지만 디자인 언어가 달라 이음매가 보입니다.

## 4. Claude 제안이 실제로 작동하는 방식

**근거 없는 제안은 만들지 않습니다.** 하드코딩된 목록이 아니라, 두 출처에서 조건이 맞을 때만 나옵니다.

**(a) 지난 회차에서 실제로 문제가 됐던 것** — 직전 회차의 실행 기록을 훑어서

- 상태가 `지연`으로 끝난 업무 → 선행 단계를 떼어내자는 제안
- 논의 기록에 **번복**이 있는 업무(이미 정한 것이 뒤집힘) → 사양을 미리 확정하자는 제안

**(b) 이번 회차의 조건이 복제 원본과 다를 때**

- 여름 회차를 복제해 겨울에 하는 경우 → 방한·난방 물품 점검 (원본 비품 목록에 아예 없는 항목)
- 1월 개회 → 폭설 대비 교통 대안 계획
- 라이브러리에 없는 항목 → 참가자 피드백 설문 준비

(b)가 특히 중요합니다. 복제만 하면 **없는 항목은 빠졌다는 사실조차 모르기** 때문입니다.

> **작동 확인 사례** — UI 테스트 중 「수련회장 계약내용 최종 조정·확인」의 상태를 지연 → 진행중으로
> 바꾸자, 그것을 근거로 삼던 「수련회장 계약 1차 체결」 제안이 목록에서 사라졌습니다.
> 제안이 정말 데이터에서 나오고 있다는 뜻입니다.

구현: `app/domain/suggestions.py`

## 5. 들어 있는 데이터

`seed.py` 를 실행하면 만들어집니다. 전화번호는 전부 자리표시자입니다.

| 회차 | 개회일 | 실행 업무 |
|---|---|---|
| **2026 여름수련회 Belong** | 2026-08-21 | **96건** |

- 업무 라이브러리 **102건** (Main 42 · 하위 52 · 일정 8) — 노션 업무 DB를 정리한 것
- 논의 내역 18건, 부서 9개, 사용자 19명

**실제 이력은 이 한 회차뿐입니다.** 분류를 그럴듯하게 보이려고 과거 회차를 지어내지
않습니다 — 지어낸 이력이 "필수 23건" 같은 판단의 근거가 되면 시스템 전체의 신뢰가
무너지기 때문입니다.

그래서 자동 분류는 **쌓인 회차 수에 맞춰 표현을 바꿉니다.**

| 쌓인 회차 | 분류 |
|---|---|
| 0 | 이력 없음 |
| 1 (지금) | 지난 회차 실행 / 지난 회차 미실행 |
| 2 | 2회 모두 실행 / 2회 중 1회 / 2회 모두 미실행 |
| 3 이상 | 필수 / 추천 / 후순위 |

마법사 3단계에 분류 근거가 몇 회차인지 표시되며, 3회차가 쌓이면 그 안내가 저절로 사라집니다.
이력이 얕은 동안 구멍 방지를 맡는 것은 **업무 라이브러리(`/library`)의 수동 필수 지정**입니다.
구멍 방지 경고는 수동 지정과 자동 판정 중 **하나라도 해당하면** 뜨므로, 이력이 하나도 없어도 작동합니다.

## 8. 정리된 판단

**상단 탭 3개의 이음매** — 회의록·수련회 진행·재정은 이전 설계 화면으로 연결돼 있습니다.
동작하는 기능을 지우지 않으려고 남겨둔 것이라, 탭에 `재설계 예정` 표시를 붙였습니다.
지우면 기능을 잃고 그냥 두면 버그로 오해하기 때문입니다.

**보드의 Phase 구분** — 관련업무 고스트와 연결 강조는 로드맵상 Phase 2 였지만 보드의 행 구조
자체라 Phase 1 에서 함께 만들었고, `CLAUDE.md` 11장의 Phase 구분도 실제에 맞게 고쳤습니다.
진단 패널은 Phase 2 로 남아 있습니다.

**화면을 고칠 때의 규칙** — 같은 종류의 버그를 반복해서 `CLAUDE.md` 10장에 못박았습니다.
세 가지입니다. (1) 속성이 아니라 화면을 확인합니다 — `el.hidden === true` 는 "숨겨졌다"는 뜻이
아닙니다. `display` 를 준 author 규칙이 `[hidden]` 을 이기므로 판정은 `getComputedStyle` 이나
`offsetParent` 로 합니다. (2) 한 동작을 확인할 때 주변이 그대로인지도 같이 봅니다 —
드로어가 열려 있는지, 부서 그룹이 펼쳐진 채인지, 스크롤이 그대로인지. (3) `innerHTML` 로 다시
그리는 핸들러는 눌린 요소가 트리에서 떨어져 나가므로, 클릭이 어디서 일어났는지 **캡처 단계에서**
기록해 둡니다.

이걸 스크립트로 돌립니다 — **`docs/checks/drawer.js`**. 보드를 열고 콘솔에 붙여넣으면 상세 패널의
모든 조작을 눌러 보고 매번 위 셋이 유지되는지 확인합니다. 반대편(빈 영역 클릭으로는 **닫혀야** 한다)도
함께 봅니다. 현재 26항목 전부 통과입니다.
