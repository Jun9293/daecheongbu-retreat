> 작성일: 2026-08-27
> 상태: **초안 (검토 필요)** — 코드 작업 전 구조/우선순위 확정용

## 0. 목적과 핵심 철학

이 시스템의 존재 이유는 단순히 "편해지는 것"이 아니라, **담당자(전도사/총무팀장/부서 리더)가 매번 바뀌어도 준비 과정에 구멍이 생기지 않는 것**입니다.

이를 위한 두 가지 설계 원칙을 세웁니다.

1. **단일 실패점(Single Point of Failure) 제거** — 한 사람이 놓쳐도 시스템이 알아차리고 다른 경로(총무팀, 관련 부서, 알림)로 다시 드러나야 함. "그 사람만 알고 있던 것"이 없어야 함.
2. **일이 스스로 굴러가는 구조** — 담당자가 할 일을 완료하면 다음 담당자에게 자동으로 넘어가고, 기한이 다가오거나 지나면 관련자 모두에게 보이도록. 사람이 매번 "확인하러 다니지" 않아도 되게.

## 1. 데이터 모델의 핵심 결정: "수련회 회차" 단위 설계

**부서명·예산 카테고리·일정 구조는 수련회마다 바뀝니다.** (여름/겨울 수련회, 담당 전도사 교체 등)

→ 모든 것을 **`Retreat(수련회 회차)`** 라는 최상위 단위 아래에 종속시키고, 매 회차마다 부서/카테고리를 새로 설정하거나 **직전 회차를 복제해서 수정**하는 방식으로 만듭니다.

```
Retreat (수련회 회차)  예: "2026 여름수련회 Belong"
 ├─ Department[]           부서 목록 (회차별로 설정, 이전 회차 복제 가능)
 ├─ BudgetCategory[]       예산 카테고리 (구분 > 항목 > 세부항목, 회차별 설정)
 ├─ ScheduleDay[]          일자 (Day-1, Day0 선발대, Day1~Day3...)
 │   └─ ScheduleItem[]     시간대별 일정 (예: "1일차 집회")
 │        └─ Task[]        해당 일정에 딸린 부서별 할 일
 ├─ Task[]                 일정에 속하지 않는 독립 할 일 (선행 준비 등)
 ├─ BudgetLine[]           예산 항목 (카테고리별 배정 금액)
 ├─ ExpenseEntry[]         실제 지출 (영수증 첨부, BudgetLine에 연결)
 ├─ Checklist[]            비품/체크리스트
 ├─ FileAsset[]            작업 파일 (버전, 상태)
 ├─ MeetingNote[]          회의록
 ├─ User[] × Role          참여자 및 권한
 └─ ActivityLog[]          모든 변경 이력 (누가/언제/무엇을, Claude 편집 포함)
```

이렇게 하면 "이번 여름수련회 기준으로 고정"과 "회차마다 다르게" 사이의 긴장이 해결됩니다 — 기본값은 직전 회차를 그대로 복제해서 시작하고, 필요한 부분만 수정하면 됩니다.

## 2. 기능 모듈 (사용자가 제시한 15개 아이디어 매핑)

### A. 일정 & 할 일 관리 *(아이디어 1, 7, 10, 12, 13)*

- **일정 타임라인**: Day별 탭, 시간대별 ScheduleItem, 부서별 필터("우리 부서 오늘 할 일만 보기")
- **선후행 의존성**: 각 Task는 `blockedBy[]`(선행 작업), `blocks[]`(후행 작업)를 가짐
  - 예: "포스터 디자인 완료" → "포스터 인쇄 발주"(후행) 가 자동으로 대기 상태에서 "시작 가능"으로 전환
  - 선행 작업이 늦어지면 후행 작업 담당자와 총무팀에게 동시에 알림 (원칙 1 반영)
- **체크리스트**: Task와 별개로, 비품/준비물 단위의 단순 체크리스트 (담당 Task에 종속 가능)
- **자동 진행 관리**: Task 상태 = `대기 / 진행중 / 피드백요청 / 완료 / 지연`
  - 마감 D-3, D-1, 당일에 담당자+총무팀에게 리마인드
  - 담당자 미지정 상태로 D-7 이내 진입 시 총무팀에게 에스컬레이션 (구멍 방지 핵심 로직)
- **부서 간 피드백 요청** *(아이디어 8)*: Task에 "관련 부서" 태그를 걸어두면, 담당자가 "확인 요청" 버튼으로 관련 부서에게 알림 + 승인/반려 코멘트

### B. 예산 관리 *(아이디어 3, 4)*

- 예산 카테고리(구분/항목/세부항목)는 회차별 설정 — 기존 시트 구조(홍보/시스템/장소비/식비/강사료/그외) 그대로 옮겨올 수 있음
- `BudgetLine`(배정 예산) vs `ExpenseEntry`(실제 지출) 를 분리해서 예산 대비 진행률 실시간 계산
- **영수증 업로드**: 지출 등록 시 사진/PDF 첨부 필수화 가능. 나중에 결산 리포트에 자동 첨부
- **결산 리포트 출력**: 교회 본부가 요구하는 양식(구분/항목/세부항목/단가/명수/횟수/예산금액/결산금액/차액 등 기존 시트 컬럼 구조)에 맞춰 엑셀/PDF로 내보내기. 양식 자체도 템플릿으로 등록해두면 다음 회차에 재사용

#### B-1. 단체 식사비 정산 (교회 규정 반영형 서브모듈)

**실제 "Belong 예산.xlsx"의 "지출 상세내역" 시트를 직접 확인해서 검증한 내용이에요.** 이 규칙은 수련회 본행사 식비(자율배식)가 아니라, **"그 외 > 수련회 준비지원 > [부서명] > 모임 식사비-N"** 항목 — 즉 준비 기간 중 부서별로 반복해서 발생하는 회식/모임 식사비에 적용되고 있었어요.

- 기존 방식: `금액`(영수증 전체 금액), `지원금액`, `비고`(여기에 "9명 박민준 홍성헌 민주아..." 처럼 인원수+명단을 자유 텍스트로 욱여넣음), `지급여부`, `지급일`, `지출자`, `지출자 계좌` 컬럼으로 관리 중
- **공식을 실제 데이터로 검증**: `지원금액 = min(금액, 인원수 × 8,000원)` — 예: 인원 12명·금액 130,600원 → 지원금액 96,000원(12×8,000 캡 적용) / 인원 9명·금액 68,900원 → 지원금액 68,900원 전액(캡 미만이라 전액 지원)
- `ExpenseEntry`에 **식사 전용 서브타입**을 추가해서, 기존에 비고 텍스트로 처리하던 인원수·명단을 구조화된 필드로 분리:
  - 영수증 금액, 식사 인원 수, 식사 참여자 명단(회원 목록에서 다중 선택 또는 수기 입력), 결제자, 결제자 계좌번호
- **자동 계산**: 위 공식을 그대로 시스템 로직으로 구현 → 초과분은 자동으로 "개인부담"으로 표시
- 결과적으로 총무팀은 "결제자에게 얼마를 돌려줘야 하는지"가 자동 계산된 **환급 대상자 리스트**(이름/계좌번호/지원금액/지급여부)를 그대로 확인 가능
- 1인당 상한 금액(기본 8,000원)은 `Retreat` 설정값으로 두어, 다른 기준(소그룹지원비 규정의 5,000~7,000원 등)이 적용되는 경우에도 재사용 가능
- 같은 부서가 "모임 식사비-1, -2, -3..." 식으로 반복 등록하는 흐름이 실제 데이터에서 뚜렷이 보였음 → 입력 폼에서 직전 등록값(부서/결제자/참석자 일부)을 기본값으로 제안하면 반복 입력 부담이 줄어듦

### C. 파일 & 작업 현황 *(아이디어 6)*

- 부서별 작업 파일 업로드 (포스터, 큐시트, 영상 등)
- 상태: `작업중 / 검토요청 / 승인 / 반려`
- 버전 이력 보관, 최신 파일 다운로드
- Task와 연결해서 "이 작업의 산출물"로 관리 → 진행 상황이 파일 유무로도 드러남

### D. 알림 *(아이디어 2, 9 — 옵션 기능)*

카카오톡을 조사해봤는데, 현실적인 제약이 있어서 정리해드려요.

| 방식 | 가능 여부 | 비고 |
|---|---|---|
| **카카오 알림톡** | 가능하지만 진입장벽 있음 | 사업자등록증(교회는 고유번호증으로 대체 가능한 경우 있음) + 카카오와 계약된 딜러사(솔라피, 알리고 등) 가입 + 발송 템플릿 사전 승인 필요. 건당 비용 발생 |
| **카카오톡 친구톡** | 상대적으로 쉬움 | 채널을 "추가"한 사람에게만 발송 가능. 무료 API 제공하는 딜러사 있음(알리고 등) |
| **웹 푸시 알림 (PWA)** | 가장 간단 | 앱처럼 홈 화면에 추가하면 브라우저 자체 푸시 가능. 별도 계약/승인 불필요, 무료 |
| **문자(SMS)** | 쉬움 | 건당 소액 비용, 딜러사 통해 바로 가능 |
| **이메일** | 가장 쉬움 | 무료, 다만 확인율이 카톡보다 낮음 |

**제안**: MVP에서는 **웹 푸시**로 시작하고, 나중에 필요하면 카카오톡 채널을 만들어 **친구톡**으로 확장하는 걸 권장해요. 알림톡은 사업자 인증·템플릿 승인 절차 때문에 초기 개발 속도를 늦출 수 있어서 후순위로 미뤄두는 게 좋을 것 같아요.

### E. 사용자 · 권한 *(아이디어 5)*

- 개인별 로그인 (전화번호 또는 이메일 + 인증코드 방식 추천 — 별도 비밀번호 관리 부담 없음)
- 역할(Role):
  - **총무팀(관리자)**: 전체 조회/편집, 회차 설정, 부서/카테고리 관리
  - **부서 리더(부장/순장)**: 자기 부서 Task/파일/예산 편집, 타 부서는 열람만
  - **부서원**: 배정된 Task만 편집, 나머지는 열람
  - **열람 전용**: 전체 진행 상황만 확인 (예: 담당 전도사가 참고용으로)
- **소속 기반 시각적 우선순위** *(아이디어 1)*: 로그인 계정의 소속 부서와 무관한 Task/일정은 완전히 숨기지 않고 **흐리게(저채도/낮은 명도) 표시** — 존재는 인지하되 내 업무에 집중할 수 있도록. 탭/필터로 "전체 보기"는 언제든 가능

### F. 회의록 *(아이디어 14)*

- 회의 생성(제목, 일시, 참석자, 회차 연결)
- 안건별 결정사항 기록
- **결정사항 → Task 자동 생성**: 회의록에서 "액션 아이템"으로 표시한 항목은 바로 담당자/기한을 지정해 Task로 전환 가능 (회의 따로, 실행 따로 → 실행이 안 되는 문제 방지)

#### F-1. 회의 녹취 음성 → 자동 분석 *(아이디어 3)*

결론부터: **가능해요, 다만 한 단계를 거쳐야 해요.**

Claude는 (claude.ai든 API든) 현재 음성 파일을 직접 "듣고" 이해하지 못해요. 텍스트/이미지/문서(PDF 등)만 입력으로 받을 수 있어요. 그래서 실제로 필요한 구조는 2단계예요.

1. **음성 → 텍스트 변환**: 녹취 파일을 별도의 음성인식(STT) API로 텍스트화 (예: Whisper API, 네이버/구글 클로바노트 등 — 어떤 걸 쓸지는 예산/화자분리 필요 여부에 따라 결정)
2. **텍스트 → Claude 분석**: 변환된 텍스트를 Claude에게 넘겨서 "회의록 요약 + 결정사항 추출 + 액션아이템(담당자/기한 추정) 초안 생성"
3. 총무팀이 추출된 액션아이템을 검토·확정하면 자동으로 해당 부서 Task로 등록

사용자 경험상으로는 "녹음 파일 업로드 → 잠시 후 회의록 초안 도착"으로 보이지만, 내부적으로는 위 2단계 파이프라인이 돌아가는 구조예요. 일반 회의와 수련회 회의가 겹치는 문제(아이디어 14의 배경)는, 회의록에 "관련 Retreat 있음/없음"을 태그해두면 검색·필터로 구분할 수 있어요.

### G. Claude 연동 편집 *(아이디어 15)*

- 시스템 내에 "설정 변경 채팅" 패널을 두고, 자연어로 "이번 회차 예산 카테고리에 '침례 준비' 항목 추가해줘" 같은 요청을 하면 Claude가 데이터 구조를 직접 수정
- 모든 변경은 `ActivityLog`에 "누가(총무 or Claude 대리 실행) / 언제 / 무엇을 왜 바꿨는지" 자동 기록되어, 나중에 이용자가 일일이 찾아다니지 않아도 변경 이력을 한눈에 확인 가능
- 기술적으로는 Claude API를 시스템 백엔드에 연결해서, 관리자 채팅 → 구조화된 명령으로 변환 → DB 반영하는 방식으로 구현 (이 부분은 Phase 3 정도로 예상)

## 3. 이용 편의성 원칙 *(아이디어 11)*

- 모바일 우선 반응형 (부서원 대부분 스마트폰으로 접속할 것으로 예상)

## 4. 기술 스택 제안

| 영역 | 제안 | 이유 |
|---|---|---|
| 프런트엔드 | 웹앱(반응형), PWA 지원 | 링크 하나로 접속, 설치 없이 사용, 푸시 알림 가능 |
| 데이터 저장 | 실제 데이터베이스 (Google Sheets 아님) | 150명 이상, 다중 동시 편집, 권한 분리, 의존성 관리 등은 시트로는 한계 명확 |
| 파일 저장 | Google Drive API 연동 | 이미 구글 워크스페이스로 협업 중이므로 익숙한 환경 재사용 가능 |
| 인증 | 전화번호/이메일 인증코드 | 비밀번호 분실 문제 최소화 |
| 알림 | 웹 푸시 → (확장 시) 카카오 친구톡 | 위 3-D 표 참고 |

## 5. 개발 로드맵 (제안)

### Phase 1 — MVP (핵심 3종)
- 일정 타임라인 + 부서별 Task (선후행 의존성 없이 기본 CRUD)
- 예산 대비 지출 관리 (영수증 업로드 포함)
- 로그인 + 기본 권한(총무팀/부서리더/부서원)

### Phase 2 — 안전망 강화
- Task 선후행 의존성 + 에스컬레이션 알림
- 파일 업로드/검토 요청 플로우
- 체크리스트, 회의록 + 액션아이템 연동

### Phase 3 — 확장
- 카카오 친구톡/알림톡 연동
- 결산 리포트 자동 양식 출력
- Claude 채팅 연동 편집

## 7. 아직 열려 있는 세부 질문

1. **음성인식(STT) 서비스**: 회의 녹취 분석(F-1)에 어떤 STT를 쓸지 — 비용, 화자분리 필요 여부, 한국어 정확도를 기준으로 다음 단계에서 후보 2~3개를 비교해드릴게요.
2. **식대 1인당 상한**: 이번 여름수련회는 8,000원이지만, 앞서 찾은 소그룹지원비 문서 기준은 5,000~7,000원이었어요. 회차/용도별로 상한이 다르다는 걸 확인했으니, `Retreat` 또는 별도 "정산 규정" 단위로 상한값을 설정하는 구조로 잡을게요 — 맞는 방향인지만 확인 부탁드려요.
3. **노션 계정 전환**: 8장 참고.

## 8. Claude가 스스로 만들고, 사용자는 결과만 리뷰하는 개발 방식

말씀하신 방식 — Claude가 Phase 1~3을 자체적으로 제작·검증·수정하고, 사용자는 최종 결과물만 확인 — 은 정확히 **Claude Code**가 만들어진 목적이에요. 정리해드릴게요.

### 왜 지금 이 채팅(claude.ai)이 아니라 Claude Code인가

이 채팅 인터페이스의 아티팩트(코드 미리보기)는 브라우저 안에서 즉석으로 돌아가는 **프로토타입**용이에요. 로그인 세션이나 데이터가 새로고침하면 초기화되고, 저장은 간단한 key-value 저장소 수준까지만 가능해요. 반면 이번 설계서에 담긴 내용 — 실제 전화번호 인증, 진짜 데이터베이스, Google Drive/카카오 API 연동, 여러 사람이 실제로 접속하는 배포된 웹사이트 — 은 실제 서버·데이터베이스·배포 환경이 있어야 가능해서, 이 채팅 밖에서 진행해야 해요.

**Claude Code**는 터미널/VS Code/데스크톱 앱에서 실제 코드 저장소를 갖고 자율적으로 코드를 작성·실행·테스트·수정하는 도구예요. 정확히 "Phase 1을 통째로 맡기고 최종 결과만 검토"하는 워크플로우에 맞아요.

### 제안하는 진행 방식

1. **이 설계 문서를 프로젝트의 "기준 문서"로 사용** — Claude Code 프로젝트 루트에 `CLAUDE.md`(또는 `docs/design.md`)로 넣어두면, 세션이 바뀌어도 Claude Code가 매번 이 구조를 참고해서 일관되게 작업해요.
2. **Phase 단위로 작업 지시** — "Phase 1의 일정·할일 관리 기능을 만들고, 완료되면 알려줘" 처럼 큰 단위로 맡기면, Claude Code가 화면/DB 스키마/API를 구현하고 스스로 실행해서 확인한 뒤 결과를 보고해요.
3. **리뷰 지점**: 각 Phase 완료 시 실행 가능한 형태(로컬 미리보기 링크 또는 배포 링크)로 결과를 받아서, 사용자는 화면을 직접 눌러보고 "이 부분만 고쳐줘" 식으로 피드백
4. **연동 활용**: 지금 이 채팅에 연결된 Google Drive(예산/일정 원본 자료), Notion(업무리스트) 데이터를 Claude Code 쪽에서도 그대로 참고 자료로 넘겨줄 수 있어요.

원하시면 지금 이 설계 문서를 기반으로 **Claude Code용 프로젝트 킥오프 문서(`CLAUDE.md`)**를 바로 만들어드릴게요 — Phase 1의 구체적인 화면 목록, 데이터 스키마, "완료 기준(Definition of Done)"까지 포함해서요.
