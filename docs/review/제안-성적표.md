# 제안 성적표 — 사람이 채웁니다

**이 표를 왜 만드는가.** 지금 제안은 **낱말 겹침**으로 고릅니다. 나중에 문장을
읽는 방식으로 바꿀 텐데, 그때 "좋아졌다" 를 말하려면 **지금 성적을 적어 둔 것이
있어야** 합니다. 없으면 바꾼 뒤에도 좋아졌는지 알 수 없습니다.

---

## 먼저 — 지난번 "22 / 27" 이 잰 것

지난 최근.md 에 **"6월까지 낸 제안 27개 중 22개가 7월 회의에 다시 나왔다"** 고
적었습니다. 그 숫자가 무엇을 잰 것인지 정확히 적습니다.

- 제안은 **회의록과 업무 이름의 낱말 겹침**으로 나왔습니다
- "7월에 다시 나왔다" 도 **같은 방식으로**, 업무 이름의 낱말이 7월 회의록에
  두 개 이상 있는지로 셌습니다
- 7월 회의는 6월 회의와 **같은 어휘를 씁니다** (같은 수련회의 같은 일)

그래서 22/27 은 **"수련회 준비 어휘가 달마다 반복된다"** 는 사실에 가깝고,
**제안이 잘 골랐다는 증거가 아닙니다.** 같은 낱말로 뽑고 같은 낱말로 채점하면
높게 나오는 것이 당연합니다.

**진짜 성적표는 사람이 눈으로 보고 맞다/아니다를 세는 것뿐입니다.** 아래가 그
자리입니다.

---

## 채우는 법

1. 개발 DB 에 6월까지 넣습니다 (운영 DB 를 쓰지 마세요)

   ```
   .venv\Scripts\python.exe scripts/import_meetings.py ^
       --retreat "2026 여름수련회 Belong" --until 2026-06-30 --batch 성적표 --apply
   ```

2. `/meetings` 에서 회의를 하나씩 열고, 제안마다 아래 표에 **O / X / ?** 를
   적습니다

   | 표 | 뜻 |
   |---|---|
   | **O** | 이 회의 내용을 그 업무에 남기는 것이 맞다 |
   | **X** | 엉뚱하다. 남기면 안 된다 |
   | **?** | 애매하다. 반반이다 |

3. 다 채우면 `--undo 성적표` 로 지웁니다

**20건쯤이면 충분합니다.** 전부 채울 필요 없습니다 — 비율만 보면 됩니다.

## 채운 뒤에 적을 것

- 언제 채웠는지, 누가 채웠는지
- **X 가 나온 것들의 공통점** — 이것이 다음에 무엇을 고칠지를 알려 줍니다
  (예: "짧은 업무 이름이 아무 회의에나 걸린다", "부서 이름이 낱말로 잡힌다")
- 그때의 방식 — `낱말 겹침 (2개 이상)`

> **문장을 읽는 방식으로 바꾼 뒤에는 이 표를 다시 채웁니다.** 같은 회의,
> 같은 20건으로 채워야 견줄 수 있습니다. 다른 회의로 채우면 두 숫자가
> 무엇을 견준 것인지 알 수 없어집니다.
