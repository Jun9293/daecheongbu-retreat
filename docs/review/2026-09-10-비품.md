# 4. 판단이 들어간 자리

1. **group_name 은 NULL 이 아니라 빈 문자열** — 지시는 「비어도 된다」 였는데 SQLite 의 유니크는 NULL 끼리를 다른 값으로 봐서 NULL 을 허용하면 (팀·묶음·이름) 유니크가 묶음 없는 품목에서 안 걸린다. 모델 주석과 4-18 에 적었다.
2. **부서 없는 체크리스트의 team_key 는 ""** — 지시가 부서 없는 경우를 말하지 않았다. 빈 키는 `can_edit_department_key` 에서 admin 만 통과하므로 「부서 없는 항목은 총무팀 소관」(그 함수의 규칙)과 맞는다. 옮기기 시험(`c02`)이 이 경우를 밟는다.
3. **같은 체크리스트에 같은 이름이 둘이면** 둘째는 (회차·품목) 유니크에 걸리므로 만들지 않고 「건너뛴 항목 N개」 로 센다 — 조용히 넘기지 않는다. **검토가 잡았다** — 세션이 autoflush=False 라 방금 add 한 run 을 select 가 못 봐서 그 가지가 실제로는 IntegrityError 였다. 이 판에서 만든 (회차, 품목)을 집합으로 들고 함께 보게 고쳤고 `c04` 가 실제로 그 자료를 만들어 잰다. 「멈추고 어느 줄인지 말한다」 쪽(import_programs 의 방식)이 아니라 「세고 건너뛴다」 로 둔 것은, 같은 이름 둘은 옮길 자료의 오류가 아니라 옛 체크리스트에 실제로 있을 수 있는 모양이고 둘째 줄이 첫째와 같은 품목이라 잃는 정보가 없기 때문이다.
4. **「더보기」 는 없어서 사이드바에만 더했다** — `/more` 는 UI 개편 단계 1 에서 지웠고 그 내용은 설정 › 점검이 됐다(14장).
5. **375 에서 펼친 줄이 176px** — 수량·위치 입력 폼과 단추 둘이 줄 아래로 내려간다. 읽고 누르는 데는 문제가 없지만 높다. 이번 지시에 화면 폭 기준이 없어 그대로 두었고 다음 UI 정리 판의 후보다. 같은 후보 하나 더(검토 9): 남의 부서 묶음의 흐림(.6)과 「불필요」 행의 흐림(.55)이 겹치면 .33 이 된다.
6. **스크립트가 `init_db()` 를 한 번 부른다** — 사람이 서버를 다시 켜기 전에 스크립트를 먼저 돌리면 표가 없어 「빈 파일을 만든 것 같습니다」 로 오해하게 된다. 부팅과 같은 함수라 이미 있으면 아무 일도 안 한다.
7. **인계의 다음 번호를 14 로 적었다** — 7번(비품)이 끝나 다음 자연스러운 것이 시트 들여오기라 그 항목을 14번으로 만들고 「다음은 14번」 으로. 순서는 사람이 바꿀 수 있다(「순서 제안, 확정 아님」).
