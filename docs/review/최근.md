## 1. 한 이름이 두 사람을 가리키고 있었습니다

성이 다른 두 사람이 있는데 대응표에는 **이름만 적힌 한 줄뿐**이었습니다.
성이 붙은 쪽은 경계 규칙 때문에 애초에 안 바뀌어 **아직 섞이지는
않았지만**, 성 붙은 형태를 잡게 만드는 순간 두 사람이 조용히 한 사람이
되고 아무 오류도 나지 않습니다.

```json
{"가명": "…", "표기": ["성이 붙은 표기", "이름만 적은 표기"]}
```

- **한 줄 = 한 사람.** 표기를 여럿 두므로 한 사람이 두 줄이 되지 않습니다
- **옛 모양 `[실명, 가명]` 도 그대로 읽습니다** — 표기가 하나뿐인 사람은
  옮길 이유가 없어 남은 27줄을 손대지 않았습니다
- **긴 표기부터 바꿉니다.** 짧은 것을 먼저 바꾸면 성 붙은 쪽이
  `성 + 가명` 이 되어 두 사람이 다시 섞입니다. **이 구조에서 가장 쉽게
  틀리는 자리라 시험으로 못박았습니다**
- **한 표기가 두 사람에게 있으면 읽기가 거절합니다.** 지금 막힌 자리가
  정확히 이것이었고, 검사가 없으면 다음에 또 조용히 합쳐집니다

> **이미 커밋된 그 가명은 전부 한 사람이고 맞습니다.** 성이 붙은 쪽이
> 애초에 안 바뀌어 섞인 파일이 없으므로 되돌릴 것이 없습니다.
> 11-2 에 적어 두었습니다 — 나중에 "왜 어떤 것은 안 바뀌어 있었나" 를
> 다시 따지지 않게.

## 2. 틈 둘을 막았습니다

### (가) `M` 뒤에 조사

```
(?<!WORDISH)(real)(?:(M)|()(?!WORDISH))
```

`M` 이 **실제로 붙었을 때만** 뒤의 한글을 허용합니다.
**느슨하게 하는 것이 아니라 좁게 더하는 것입니다.**

| | |
|---|---|
| `담당자가 ◯◯M으로 정해짐` | → `가명M으로` (바뀜) |
| `필요한 것들` · `진행요원` · `중요한 결정` · `사진 촬영` · `이동은 명시적으로` | 그대로 (0곳) |

`M` 이 없으면 영향이 0이고, 앞쪽 경계는 그대로라 낱말 안에 든 것은
여전히 안 바뀝니다.

### (나) 성이 붙은 이름

대응표의 새 구조로 표기 목록에 넣어 처리했습니다. **찾는** 쪽
(`check_names.py`)은 원래부터 경계를 안 보므로 그대로 잡습니다.

## 3. 넘김 목록의 눈금 — **위치가 아니라 길이**

**이름의 위치로 가르지 않았습니다.** 이 자료에서 이름은 낱말 한가운데
오는 것이 정상입니다 — `◯◯M으로` · `9명 ◯◯◯ ◯◯◯`. 위치로 가르면
**잡던 것을 놓칩니다.**

| 이름 길이 | 어떻게 보나 |
|---|---|
| 두 글자 이상 | 그대로 느슨하게 (오탐이 거의 없음) |
| **한 글자** | **홀로 섰을 때만.** 앞뒤가 한글이면 안 봄 |

낱말 안에 든 한 글자는 `anonymize.py` 의 경계 규칙에 맡깁니다.
그러지 않으면 목록이 낱말 수만큼 늘어나고, **늘어난 목록은 아무도 읽지
않습니다** (4-11).

**넘김 목록이 133줄 → 10줄** 입니다. `진행`·`사진`·`추진력`·`필요한`
류가 한꺼번에 빠졌습니다.

```
◯행 중입니다      -> 안 걸림
담당은 ◯ 입니다    -> 걸림      ← 옛 방식에서는 이것도 안 걸렸습니다
```

### `[사람]` 표시

목록에 두 종류가 섞여 있습니다 — 규칙이 낸 것과 **자동 분류가 틀려서
사람이 뒤집은 것.** 둘째가 훨씬 값집니다. 자동 분류가 **어디서 틀리는지의
기록**이기 때문입니다. 지금은 `이동은` 한 줄입니다(`이동` + 조사 `은`
인데 제 분류가 `성 + 이름` 으로 봤습니다).

성적표의 「X 이유를 셀 자리」와 같은 자리입니다 — 세지 않으면 무엇을
먼저 고칠지가 인상으로 정해집니다.
