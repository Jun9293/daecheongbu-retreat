## 1. 1단계 — 글자가 흐렸던 이유는 문서가 자기 기준을 어겨서다

9장은 "혼자 뜻을 지는 글자는 4.5:1 이상" 이라고 해 놓고, 바로 아래에서
`--ink-2: #787774` 를 **"4.4:1 로 사실상 기준선"** 이라고 적고 있었습니다.
재 보니 **4.48:1**, 기준을 못 넘는 값이 기준으로 쓰이고 있었습니다.
그 값이 사이드바·보조 글자 전부에 걸려 있어 화면 전체가 흐렸습니다.

### 잰 값 — 바꾸기 전후

| 토큰 | 값 | 흰 바탕 | `#F7F7F5` 위 |
|---|---|---|---|
| `--ink` | `#37352F` (그대로) | 12.26:1 | 11.43:1 |
| `--ink-2` | `#787774` → **`#6E6D6A`** | 4.48 → **5.17** | 4.17 → **4.82** |
| `--ink-3` | `#9B9A97` → **`#83827F`** | 2.81 → **3.84** | 2.62 → **3.58** |

**색상은 그대로 두고 명도만 내렸습니다** — 여전히 따뜻한 회색이고 검정으로
가지 않습니다(4-0). 본문은 이미 충분해서 건드리지 않았습니다.

**`--ink-3` 은 일부러 4.5 를 넘기지 않았습니다.** 넘기면 보조와 구별되지 않아
위계가 무너집니다. "장식 자리에만 쓴다" 는 규칙은 그대로 두고, 다만 2.81:1 은
그 자리에도 너무 옅어서 3.5:1 위로 올렸습니다.

브라우저에서 확인한 실제 계산값 — 사이드바 항목 `rgb(110,109,106)`(=`#6E6D6A`) ·

9장의 문단을 새 값으로 고치되 **옛 값이 기준선이었다는 기록은 남겼습니다** —
무엇에 당했는지가 지워지면 다음 사람이 같은 값으로 되돌립니다.

## 2. 2단계 — 비침이 안 보인 진짜 이유

옅어서만이 아니었습니다. **`.out`(이 달 밖) 칸이 이미 회색인데 비침도
회색이라, 비침이 '이 달 밖' 으로 읽혔습니다.**

```
지금 비침(호버 면 두 겹) = #E8E8E7
이 달 밖(.out)          = #F6F6F6
→ 둘 사이 ΔE            = 4.9      ← 사람이 겨우 알아보는 거리가 2.3
```

밝기만 조절해서는 안 되고 **색상**이 있어야 갈립니다.

### 고른 색과 왜 그것인지

**`--span: #FAF1D2` (옅은 앰버).** 소거법으로 골랐습니다.

| 후보 | 왜 아닌가 |
|---|---|
| 붉은 계열 | 지연 `--now:#C4554D` 및 그 틴트 `#FBF1F0` 과 뜻이 섞입니다 |
| 파랑 | 선택·오늘 테두리 `--link:#2383E2` 와 같은 뜻으로 읽힙니다 |
| 초록 | **이 화면에서 이미 뜻이 있습니다** — `--go:#4C8A5E` 가 완료·진행 가능·체크에 쓰입니다 |
| **앰버** | 남은 것이고, "구간을 형광펜으로 그은" 관용에도 맞습니다 |

### 지연·선택과 어떻게 갈리는지 (잰 값)

| 견준 것 | ΔE |
|---|---|
| 흰 칸 | **16.9** |
| 이 달 밖 `#F6F6F6` | **16.3** |
| 지연 틴트 `#FBF1F0` | **15.3** |

전부 옛 4.9 의 3배 이상이고, 무엇보다 **무채색이 아니라** `.out` 과 뜻이
섞이지 않습니다.

### 위에 얹히는 것이 그대로 읽히는가 — 브라우저에서 확인

비침은 배경일 뿐입니다. 실제로 클래스를 붙여 놓고 계산값을 읽었습니다.

| | 비침 전 | 비침 위 |
|---|---|---|
| 오늘 칸 배경 | `rgba(55,53,47,.043)` | `rgb(241,233,203)` (`--span-out`) |
| 오늘 칸 테두리 | `rgb(35,131,226) 0 0 0 2px inset` | **그대로** |
| 오늘 칸 날짜 글자 | `rgb(35,131,226)` | **그대로** |
| 지연 점 채움 / 테두리 / 글자 | — | `rgb(251,241,240)` / `rgb(196,85,77)` / `rgb(163,66,59)` — **전부 그대로** |

대비비로도 — 점의 글자 10.85:1 · 오늘 테두리 3.43:1 · 지연 테두리 3.91:1.

**값은 이름 있는 토큰 하나입니다** (`--span`, 그리고 `.out` 칸용 `--span-out`).
전에는 반투명을 두 겹 얹어서 **실제 색이 CSS 어디에도 없었고** 다음 사람이
계산해야 했습니다.

`test_t_04c_비침은_무채색이다` 는 **그 시험이 지키던 것이 틀렸으므로**
`test_t_04c_비침이_지연_선택_이_달_밖과_갈린다` 로 이름과 내용을 함께 바꿨습니다.

## 3. 3단계 — 해시를 경로로

`?v=<해시>` 가 통하려면 Cloudflare 캐시 키에 쿼리가 들어가야 하는데 **그
스위치는 이 저장소에 없습니다.** `Ignore Query String` 으로 바뀌는 순간
**1년짜리** 옛 파일을 물게 됩니다 — 지난번 4시간보다 훨씬 나쁩니다.

```
/static/js/calendar.f8bcd26e.js      ← 실제로 화면이 부르는 주소
/static/css/retreat.a5de97b4.css
/static/js/drawer.0267706c.js
```

`main.HashedStatic.get_path()` 가 `이름.<8자리>.확장자` 에서 해시를 떼고 실제
파일을 내줍니다. **해시가 붙어야 하는 종류(`.js`·`.css`)인데 안 붙어 있으면
없는 파일로 둡니다** — 그것이 이 방식의 값어치입니다. `?v=` 는 빠뜨려도 아무
일이 없어서 한 화면이 몇 달 동안 1이었습니다.

- **해시가 맞는지까지는 보지 않습니다.** 요청마다 파일을 다시 뜰 값을 치를
  이득이 없습니다 — 막으려던 것은 해시를 아예 안 붙이는 것이고, 덤으로
  **열어 둔 옛 탭이 계속 돕니다**(새로고침하면 새 주소를 받습니다)
- **아이콘·매니페스트에는 안 붙입니다.** `sw.js` 와 `manifest.webmanifest`
  가 고정 주소로 가리키고 있어 붙이면 그쪽이 못 찾습니다

> **`sw.js` 를 함께 고쳐야 했습니다.** 미리 받는 목록에 `/static/css/app.css`
> 와 `/static/js/app.js` 가 박혀 있었는데, 이제 그 주소는 404 입니다.
> **틀린 주소가 하나라도 있으면 `addAll` 이 통째로 실패하고 서비스워커가
> 설치되지 않습니다** — 그러면 푸시도 함께 죽습니다. 해시가 안 붙는 아이콘만
> 남기고 캐시 이름을 `dcb-v3` 으로 올렸습니다.

## 7. 6단계 — 도장이 무엇을 지키는가

```js
__unusedFor: 'f2eee996',
```

`drawer.js` 의 **머리말 주석 블록 + `call('...')` 이름 목록**만 해시로 뜬
값입니다. 계약이 바뀌면 도장이 안 맞아 빨개지고, 그때 `__unused` 를 처음부터
다시 읽습니다.

**파일 전체를 뜨지 않는 것이 핵심입니다** — 무관한 수정에 걸리면 사람이
읽지 않고 도장만 찍게 되고, 그러면 이 장치는 없는 것과 같습니다.
`test_w_18` 이 그 둘을 다 봅니다:

| 무엇을 바꾸면 | 도장 |
|---|---|
| 끝에 주석 한 줄 | 그대로 |
| 머리말 밖의 상수 이름 | 그대로 |
| `call('onStatus')` → `call('onStatus2')` | **바뀐다** |
| 머리말 한 글자 | **바뀐다** |

시험이 실패할 때 **무엇을 다시 읽어야 하는지**를 메시지에 적었습니다 —
"`__unused` 목록을 처음부터 다시 읽는다 … 도장만 바꾸고 넘어가면 이 장치는
없는 것과 같다."

3단계의 정적 주소 해시와 같은 수법입니다 — **내용이 바뀌면 이름도 바뀌게
해서, 옛것을 조용히 쓰지 못하게 합니다.**
