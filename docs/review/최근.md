## 판단이 들어간 자리 (검토·사람 판정 요청)

1. **바·점을 한 규칙으로** — 1-b 가 저장 '지연' 을 없애면, 바만 저장 상태로 칠하던
   옛 규칙에서는 보드의 지연 표현이 영영 안 나옵니다. 4-3 옛 메모의 「표현 4종은

   반대 방향을 재던 `test_r2_02b` 를 뒤집어 다시 적었습니다
2. **「목록과 같은 partial」 의 해석** — 행의 뼈대(taskrow 매크로: 제목·태그·부서
   칸·칸들)를 한 벌로 공유하고, 칸의 내용은 화면이 채웁니다(목록: 담당자·마감·배지,
   마법사: 이력 막대·D-주차·시작일 + 체크박스). 두 화면의 자료가 달라 칸 구성까지
   같게 할 수는 없었습니다
3. **옛 /tasks 시험 정리** — 라우터와 함께 죽은 기능(선행 지정 폼·시작가능 알림·

   바꿨습니다. 순환·자기참조는 `test_dependencies.py` 가, 새 선행은
   `test_prerequisites.py` 가 이미 지킵니다. 확인 요청 생성은 단계 4 전까지
   화면에서 만들 길이 없습니다(응답 흐름 `/reviews/{id}/respond` 는 살아 있음)
4. **apply 의 다중 걸기** — 엔드포인트는 `run_ids` 를 받지만 회의록 화면(meeting.js)은
   아직 하나만 보냅니다(옛 모양도 받음). 여러 업무를 고르는 UI 는 이 단계 범위에
   없다고 읽었습니다

   필요해 `_ADDED_COLUMNS` 로 붙이고 8장에 한 줄 적었습니다. 운영 DB 에 반영된

6. **push 알림 링크** — 4-11·4-16 이 `/tasks?task=` 라고 정해 두었는데 코드가
