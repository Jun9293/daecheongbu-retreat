## 1. 현황 브리핑을 오늘 것으로 (S-i)

**기준일을 오늘로 올렸습니다.** 그 문서가 하는 일은 「지금 어디까지 와
있나」 를 한 장으로 보여주는 것이라 오늘 값이 맞습니다. 「그때의
스냅샷」 이라고 적어 두면 **읽는 사람이 언제 것인지 매번 계산해야 하고**,
그건 5-8 이 경계한 자리입니다.

`git diff --cached -U0` 로 실제로 바뀐 줄은 이 셋입니다.

```
- 기준일: 2026-09-01
- 상태: … 테스트 918건 통과, 상세 패널 점검 48항목 통과
- 코드는 GitHub 비공개 저장소 … (커밋 40개)
+ 기준일: 2026-09-05
+ 상태: … 테스트 918건 통과, 상세 패널 점검 보드 61항목 · 달력 62항목 통과
+ 코드는 GitHub 공개 저장소 … (커밋 164개) —
+   2026-09-01 에 공개로 바꿨습니다. 저장소에는 실명이 하나도 없습니다 (CLAUDE.md 11-2)
```

**「비공개」 가 가장 무겁습니다.** 2026-09-01 에 공개로 바꿨고, 이건
숫자가 아니라 **실명 판단의 전제**입니다 — 그 문서를 읽고 「비공개니까
괜찮겠지」 로 판단하면 정확히 이 프로젝트가 두 번 겪은 사고가 납니다.
그래서 공개로 고치면서 **「저장소에는 실명이 하나도 없습니다」** 를
한 줄 붙였습니다.

**「48항목」 도 낡았습니다.** CLAUDE.md 10장이 「지금은 **보드 61항목 ·
달력 62항목**입니다」 라고 적어 두었습니다 — 달력이 생기면서 늘어난
것을 브리핑이 안 따라왔습니다.

## 2. 「이 셋이 전부가 아니다」 를 정본으로 (S-f)

지금까지 시험 주석에만 있어서 **규칙을 읽고 문서를 적는 사람은 그
경계를 못 봤습니다.** 셋(`sc` · `curl` · `where`)만 적혀 있으면
「이 셋만 조심하면 된다」 로 읽힙니다 — 11-3 되짚는 목록의
**「언제 조심할지를 정하는 규칙은 그 언제가 아닌 때에 조용히 뚫린다」**
자리입니다.

`CLAUDE.md` 11-2 의 별칭 규칙에 넉 줄을 더했습니다.

> **이 셋이 전부가 아닙니다.** 새 명령을 문서에 적을 때
> `Get-Command <이름> -All` 로 한 번 봅니다 — 여기 없다고 안전하다는
> 뜻이 아닙니다. 실제로 `curl` 은 잡고 `sc` 는 못 잡아 판을 한 번
> 더 돌았습니다.

**두 글이 같은지 기계로 견줬습니다.**

```
CLAUDE.md 에 그대로 있나  : True
시험 주석에 그대로 있나   : True
두 글이 한 글자도 안 다른가: True
```

**정본이 어디인지 양쪽에 적었습니다.**

- `CLAUDE.md` — 「**이 11-2 가 정본이고** 그 시험의 주석은 여기서 옮겨
  간 것입니다 — 한쪽만 고치면 기준 문서와 시험이 서로 반대를 말합니다」
- `tests/test_docs_shell.py` — 「**정본은 CLAUDE.md 11-2 다** — 위 넉
  줄은 거기서 옮겨 온 것이다」

지난 판이 겪은 **「한 사실을 두 곳에 적고 한쪽만 고쳤다」** 를 또 만들지
않으려는 것입니다.

> **다만 이것도 사람이 기억해야 하는 규칙이지 검사가 아닙니다.**
> 두 글이 갈려도 918 은 그대로 초록입니다 — `봐둘것.md` 의 S-g 가
> 그 자리이고, 이번 판에서 고치지 않았습니다.
