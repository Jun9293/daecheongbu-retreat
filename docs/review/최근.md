## 3. `/dates` 응답에 무엇을 더했는가

생김새를 만드는 곳을 **`app/domain/board.py` 의 `paint_of()` 하나**로 모으고,
`/status` 와 `/dates` 가 그것을 그대로 실어 보냅니다. `calendar.dot_of()` 도
같은 함수를 부릅니다 — 처음 그린 점과 옮긴 점이 같아야 하기 때문입니다.

```
status · color · overdue · overdue_days
background · border            ← 보드의 바
dot_background · dot_border    ← 달력의 점
```

**왜 둘로 나눠 보내는가** — 규칙이 다릅니다. 보드의 바는 저장된 상태 그대로
칠하고, 달력의 점은 **기한이 지났으면 '지연' 으로 바꿔** 칠합니다(4-13).
그래서 한 값으로 합칠 수 없고, 그렇다고 화면마다 계산하게 두면 두 벌이 됩니다.
`test_r2_02b` 가 기한 지난 '대기' 업무에서 `background != dot_background` 임을
확인해 이 구분이 살아 있는지 봅니다.

| | 전 | 후 |
|---|---|---|
| 보드 `/status` | `bar_style(run.status …)` 를 라우터에서 직접 | `paint_of` |
| 달력 첫 렌더 | `calendar.dot_of` 가 따로 계산 | `paint_of` |
| 달력 날짜 이동 | **화면에서 `iso < today`** | `paint_of` (서버) |
| 보드 날짜 이동 | 색을 안 건드림 | `paint_of` 를 받아 칠함 |

보드 쪽은 **지금은 값이 같습니다** — 바는 저장된 상태로만 칠하므로 날짜만
옮기면 색이 바뀔 일이 없습니다. 그래도 받아서 칠하게 둔 이유는, 규칙이 바뀌었을
때 따라오지 않는 자리가 바로 어긋나는 자리이기 때문입니다. 사실대로 적습니다.

> 한 가지 곁들여 고쳤습니다 — `paint_of` 가 `color_tag` 대신 `color` 를 씁니다.
> 색을 안 정한 부서에서 `color_tag` 는 `None` 이고, 그대로 내보내면 화면이
> `border-color: None` 을 받습니다. `color` 는 그 자리에 기본색을 넣는 속성입니다.

## 9. 판단이 들어간 자리

**`data-today` 를 템플릿에서 뺐습니다.** 화면이 날짜를 견주지 않게 되었으므로
쓰이지 않습니다. 안 쓰는 값을 실어 보내면 다음 사람이 "이걸로 뭔가 하는군" 하고
다시 계산을 붙입니다.

**시험이 주석을 코드로 착각하지 않게 `code_only()` 를 뒀습니다.** 이 저장소는
"왜 그렇게 했는가" 를 주석에 길게 적으므로, 고친 내용을 설명한 문장이 그대로
시험에 걸립니다 — 실제로 `iso < today` 를 **지웠다고 적은 주석** 때문에
"아직 견주고 있다" 로 잘못 읽혔습니다.

**보드의 색 반영은 지금 효과가 없습니다.** 위 3장에 적은 그대로이고, 그래도
넣은 이유는 두 벌이 다시 생기지 않게 하기 위해서입니다. "지금 값이 같으니
안 해도 된다" 가 바로 이번에 고친 문제의 출발점이었습니다.
