**가려진 `def` 는 애초에 수집되지 않기 때문입니다.** 중복이 있어도

`표본 = [...]` 가 오면 함수가 사라지는 것도 같은 고장입니다.

되돌려 확인한 둘:

- 일부러 함수 하나를 두 번 적으니 **빨감**

**(1) 「공개본 검사가 키 검사보다 앞인가」 — 실제로 돌게 옮겼습니다.**

소스를 안 읽고 잽니다. **키를 없애고** 공개본에 사람이 채운 것을 둔
채 `main()` 을 부릅니다 — 공개본 검사가 앞이면 가드로 **exit 4**,
뒤집히면 키 오류로 **exit 2** 입니다. 두 숫자가 순서를 그대로 말합니다.

소스에서 두 블록을 실제로 맞바꿔 보니 **exit 2 로 빨갰습니다**
(`키 검사가 먼저 걸렸다 — 공개본 검사가 뒤에 있다`).

순서가 왜 중요한가 — 키 검사가 앞이면 키가 있는 사람은 그냥 지나가서
**돈을 다 쓰고 `.real` 을 덮은 뒤에** 멈춥니다. 그때
「아무것도 쓰지 않았습니다」 가 거짓말이 됩니다. 그래서
`not 실명본.exists()` 도 함께 봅니다.

**(2) 「`공개본()` 안에 `막는다(` 가 없는가」 — 버렸습니다.**

코드가 어떻게 생겼는지를 보는 것이지 무엇을 하는지가 아닙니다.
(1) 이 순서를 실제로 재므로 안이든 밖이든 결과로 걸립니다.

## 2. [G1] 담당칸 — 「어디의 무엇」 한 목록에서

`담당칸` 을 JSON 갈래만 쓰고 DB 갈래는 자기 목록을 따로 들고
있었습니다. **넷째를 더해도 DB 는 안 따라옵니다** — 「늘어나면 여기
더한다」 는 주석이 절반만 사실이었습니다.

**이 검사가 고친 고장이 「보는 목록이 불완전했다」 인데, 같은 모양이
한 칸 옆에 있었습니다.**

```python
담당칸 = (
    ("json", "assignee"),
    ("json", "assignee_name"),
    ("json", "host"),
    ("db", "program_items", "assignee_name"),
    ("db", "programs", "host"),
)
JSON칸 = frozenset(x[1] for x in 담당칸 if x[0] == "json")
DB칸 = tuple((x[1], x[2]) for x in 담당칸 if x[0] == "db")
```

시험 둘이 이어서 지킵니다.

- `test_표밖_05` — 가짜 DB 를 두고 **목록에서 그 칸을 빼면 안 보이는
  것**으로 잽니다. 박아 두었다면 빼도 그대로 보입니다.
  실제로 옛날처럼 박아 넣으니 **빨갰습니다**
  (`목록에서 뺐는데도 봤다 — DB 갈래가 자기 목록을 따로 든다`)
- `test_표밖_06` — 그 `DB칸`·`JSON칸` 이 `담당칸` 그대로인지를
  **값끼리** 견줍니다. 05 가 「`DB칸` 을 쓴다」 까지만 재므로
  어디서 왔는지를 여기서 잇습니다

담당자 칸 **482개 그대로** · 표밖 **0개** — 동작은 안 바뀌었습니다.

   수집되지 않으므로 중복이 생겨도 사라져도 수가 같습니다 —
   「905 였어야 한다」 는 셈 자체가 성립하지 않았습니다.
   **세는 것으로 못 잡는 고장은 이름을 봐야 합니다**

4. **「보는 목록이 불완전하다」 를 막으려고 만든 검사가 세 번째로
