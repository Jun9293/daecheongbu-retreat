# 1. 0단계 — 노션 페이지의 부모

**0a · 0c — 부모는 전부 데이터 소스다.**
- 노션 업무 DB 는 데이터 소스 하나이고, 읽기 전용 SQL 로 센 줄이 **257** 이다. 앱이 들여온 파일의 id **257 개가 그 257 줄과 하나도 빠짐없이 같다**(SQL 에 id 목록을 넘겨 셈 · 257/257).
- 노션에서 **DB 의 줄(페이지)의 부모는 늘 그 DB** 다 — 다른 페이지 아래 중첩된 페이지는 DB 의 줄이 될 수 없다. 그래서 257 줄 모두 부모 종류가 「데이터 소스(DB)」 이고, **「다른 페이지의 자식(page_id)」 은 0 · 「워크스페이스」 는 0** 이다.
- 표본으로 넷을 직접 열어 부모 경로를 봤다 — Sub 하나 · Sch 하나 · Main 하나 · 속성 빈 줄 하나. 넷 다 「DB → 그 DB 를 품은 수련회 페이지」 로 같았다.
- 수를 맞췄다 — 257 = D-주차 표지 24 + 233. 233 = Main 87 + Sub 74 + Sch 62 + 속성 빈 줄 10. 앱의 노션 업무 233 = main 97(Main 87 + 빈 줄 10, 들일 때 `--구분없음 main`) + sub 74 + schedule 62 로 맞는다. **앱에서 부모가 채워진 것은 0**.

**0b — 부모가 페이지인 것이 없어 해당 없다.**

**그런데 「종속」 은 다른 길로 그려지고 있었다.**
- 표본 Main 페이지 본문 맨 위에 **그 DB 를 보는 인라인 보기**가 있고, 그 보기의 이름은 「관련 업무/일정」, 필터는 **「관련업무 가 이 페이지를 담는다」** 다. 부모 경로를 보면 그 보기의 부모가 그 Main 페이지다(보기이지 줄이 아니다).
- DB 의 **Main 템플릿**에 사람에게 주는 안내가 적혀 있다 — 아래 표에서 「관련업무」 필터로 현재 페이지를 고르고, 현재 페이지의 「관련업무」 에 관련되는 업무 페이지들을 모두 추가하라는 것. 템플릿 본문에도 같은 인라인 보기가 있다.
- 그래서 **총무님이 본 「Main 아래 종속된 서브 · 일정」 은 페이지 중첩이 아니라 Main 페이지 안의 필터 보기**다. 그 필터가 쓰는 것이 `관련업무` 관계다. 모든 Main 페이지가 그 보기를 가졌는지는 **다 열어 보지 않았다**(표본 Main 하나 · 템플릿 둘).

# 2. 1단계 — 다른 실마리

**1a — 놓친 관계 속성은 없다.** 데이터 소스의 속성은 모두 **열둘**이고, 관계(relation) 속성은 **`관련업무` 하나**뿐이다(대상은 같은 DB). 「상위 업무」 · 「Parent task」 · 노션의 하위 항목 기능이 만드는 상위/하위 관계 속성은 없다. 나머지는 제목 · 담당팀 · 관련 팀 · 업무속성 · 진행 상황 · 행사 전후 · 일자 둘 · 설명 · 참여자 · 사람 · 파일이다.

**1b — `관련업무` 가 실제로 부모를 가리키는 데 쓰인다.** Main 이 아닌 줄(146)에서 `관련업무` 가 가리키는 **Main** 을 셌다.

|---|---|---|---|---|---|
| Sub | 74 | 53 | 11 | 9 | 1 |

- **맞물림(양쪽에 서로 적힘)** — 「Main 을 하나만 가리킴」 84 가 **모두** 그 Main 쪽 `관련업무` 에도 되돌아 적혀 있다(84/84). 관계가 양방향으로 쓰인다
- **담당팀이 다른 부모** — 84 중 10(Sub 2 · Sch 7 · 빈 줄 1)은 가리킨 Main 의 담당팀이 자기와 다르다
- **Main 끼리도 `관련업무` 로 이어져 있다** — Main 87 중 30 이 다른 Main 을 가리킨다(하나 14 · 여럿 16). 같은 관계가 「부모」 와 「그냥 관련」 을 함께 담는다는 뜻이다 — 2장 표가 섞지 말라는 두 관계다
- **앱이 들인 관계와 수가 같다 — Sub · Sch 에서.** 운영 DB 의 `related_library_ids` 로 같은 규칙을 셌더니 Sub(53 · 11 · 9 · 1)와 Sch(30 · 5 · 1 · 26)가 위 표와 **한 자리도 안 다르다**. **속성 빈 줄 10 은 다르다** — 앱에는 `kind=main` 으로 들어가 있어 앱의 `kind` 로 Main 을 가르면 그 10 이 Main 쪽으로 가고, Main 하나만 가리킴이 83 · 담당팀 다른 부모가 9 · Main 끼리가 33 이 된다(커밋 전 검토가 다시 잼). 그래서 위 표의 수(100)를 얻으려면 **노션 업무속성으로 갈라야** 하고, 그것은 이미 들여온 저장소 밖 파일(`data/노션업무전체.real.tsv`)에 있다 — 다음 판도 노션을 다시 부르지 않는다

**1c — 제목에서 계층을 읽을 길은 없다.** 숫자로 시작하는 제목은 **233 중 1**(Main)이고 「1-1」 같은 번호 짜임은 없다. 「Main 제목으로 시작하는 제목」 은 위 84 가운데 **28** 에서만 맞아 떨어진다 — 확인용 보조는 되어도 소스는 못 된다.
