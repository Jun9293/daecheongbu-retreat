## 1. 대응표를 읽는 곳을 하나로

**"같은 것을 두 곳에서 읽는" 문제가 이 작업에서만 네 번째**였습니다.
마지막 것은 `test_x_21` 이 대응표를 직접 파싱하다 새 구조에서
`KeyError` 로 깨진 것입니다.

**읽는 함수가 원본 구조를 돌려주지 않게 했습니다.** `dict` 를 그대로 주면
부르는 쪽이 구조를 알게 되고, 구조가 바뀌면 부르는 쪽이 깨집니다.

| 물음 | 함수 |
|---|---|
| 찾아야 할 표기 전부 (긴 것부터) | `표기들()` |
| 이 표기가 무엇으로 바뀌는가 | `가명(표기)` |
| 대응표에 든 **사람** 수 | `사람수()` |
| 이름 표기 수 (사람수보다 크면 표기를 여럿 둔 사람이 있다) | `표기수()` |

**`load_map()` 을 밖에서 부르는 곳이 이제 하나도 없습니다** —
`check_names` · `test_x_21` · `test_anonymize_map` · `test_check_names`
전부 옮겼습니다.

### 지키는 방법도 바꿨습니다

전에는 `json.loads` 가 없는지를 **글자로** 찾았습니다. 그건 10장이 네 번
당했다고 적은 그 함정입니다 — **코드와 설명을 못 가립니다.**

대신 **대응표 파일 이름이 `.py` 코드에 몇 번 나오는지 셉니다.**
주석에 나와도 세면 되므로 오탐이 없고, 새로 읽는 곳을 만들면 반드시
걸립니다. 지금 **1** 입니다.

> 시험 자신은 그 문자열을 쪼개서 씁니다(`"anonymize-map" + ".json"`).
> 안 그러면 **자기가 세어져 둘이 됩니다** — 10장의 자기참조가 또 나온 자리라
> 만들면서 바로 걸렸습니다.

`CLAUDE.md` 14장에 줄을 더했습니다.

## 2. 시험의 식대 명단에서 사람 이름을 뺐습니다

**먼저 무엇을 재는 시험인지 봤습니다.** `app/routers/expenses.py` —

```python
def parse_attendees(raw: str) -> list[str]:
    return [name for name in re.split(r"[,\n\r\t ]+", raw.strip()) if name]
```

**구분자로만 자릅니다. 글자 수가 파싱에 영향을 주지 않습니다.**
시험이 재는 것은 지원금액 계산(`min(130,600, 12 × 8,000) = 96,000`)과
목록 왕복입니다. 그래서 **길이를 지킬 이유가 없어** `이름1 이름2 이름3`
으로 바꿨습니다. 쉼표가 섞인 자리(`이름1 이름2, 이름3`)는 구분자를 재는
것이라 그대로 뒀습니다.

가명으로 바꾸지 않은 이유는, 그러면 **대응표에 매여 대응표가 바뀔 때마다
시험이 함께 흔들리기** 때문입니다.

> `app/templates/expenses.html` 을 한 번 바꿨다가 **되돌렸습니다** —
> 「하지 않을 것」에 들어 있었습니다. 그래서 남은 것이 정확히 다섯입니다.

### 남은 다섯

```
CLAUDE.md | 1475 | 홍◯◯
CLAUDE.md | 1475 | 민◯◯
CLAUDE.md | 1672 | 이◯◯
app/templates/expenses.html | 74 | 홍◯◯
app/templates/expenses.html | 74 | 민◯◯
```

대응표 방식(표기 목록에 성 붙은 형태를 더하기)으로 고칠 것들이라
**main 에 합친 뒤 별건으로** 합니다.

## 3. 10장의 자기참조를 사실에 맞췄습니다

*"거의 늘 넷"* 이 **같은 작업 안에서 다섯**이 됐습니다. 규칙이 틀린 것이
아니라 **그때 없던 파일이 새로 생겼기** 때문입니다 — 도구가 자라면
자리도 늘어납니다. 그래서 **세어 두지 않습니다.**

그리고 **자리를 아는 것과 예외로 두는 것은 다릅니다.** 검토 보고는
자리이지만 **예외가 아닙니다** — 운영 자료에서 온 것을 계속 담을 파일이라
빼면 정확히 새는 자리를 안 보게 됩니다.

`check_names` 독스트링에 한 줄 적었습니다 — *"이 검사를 손댈 때는 주석만
적힌 상태에서 한 번 돌리세요."* 다 만들고 돌리면 다섯 번 빨개진 뒤에
압니다.
