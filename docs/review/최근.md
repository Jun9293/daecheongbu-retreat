## 0. 먼저 — 재시작 스크립트의 판정 (0단계)

지적이 맞았습니다. **다만 방향이 반대였습니다.**

```
$전 = @(100,200); $후 = @(100,200)   # 옛 프로세스가 그대로
($후 -ne $전)  →  100, 200           # 비지 않는다
if 판정        →  True               # "성공 — PID 가 바뀌었습니다"
```

배열끼리의 `-ne` 는 왼쪽 원소 하나하나를 **오른쪽 배열 전체**와 견주므로
아무것도 같지 않고, 결과가 비지 않아 `if` 가 참이 됩니다. 그래서 **새로 뜨지
않았는데 "성공"** 이 뜹니다 — 이 스크립트가 막으려던 바로 그 착각입니다.

겹치는 PID 로 견주도록 고쳤고, 일곱 경우를 전부 돌려 봤습니다.

| 전 → 후 | 판정 |
|---|---|
| 30456 → 31872 | 성공 |
| 30456 → 30456 | 실패 — 30456 이 그대로 |
| 100,200 → 300,400 | 성공 |
| 100,200 → 100,200 | 실패 — 100, 200 이 그대로 |
| 100,200 → 100,300 | 실패 — 100 이 그대로 |
| 100,200 → 200 | 실패 — 200 이 그대로 |
| 100,200 → (없음) | 실패 — 다시 뜨지 않음 |

안내서에는 스크립트가 **한 벌뿐**이라(12-1) 그 자리만 고쳤고, 다음 사람이
다시 `-ne` 로 줄이지 않도록 **왜 안 되는지**를 그 아래에 적었습니다.

## 2. 비침의 색 — **무채색입니다**

`rgba(55,53,47,.06)`(4-0 의 호버 면)을 **두 겹** 얹었습니다. 부서 색은
쓰지 않았습니다.

지시문에 "부족하면 부서 색을 낮은 농도로" 라는 갈래가 있었지만 **고르지
않았습니다.** 4-0 이 "부서 색으로 면을 채우지 않는다 — 화면이 색으로 덮이면
정작 눈에 띄어야 할 **선택 테두리와 지연 배지가 묻힌다**" 고 못박고 있고,
비침이 뜨는 순간이 바로 그 둘을 봐야 하는 순간입니다. 지연 점이 붉은 칸에
붉은 비침을 얹으면 무엇이 지연인지 흐려집니다.

한 겹으로는 104px 짜리 큰 칸에서 너무 옅어 두 겹으로 했습니다. 색을 새로
만든 것이 아니라 **있는 토큰을 겹친 것**이라 4-0 의 "새 색을 만들지 않는다"
안에 있습니다. `test_t_04c` 가 이 자리에 `#`·`rgb(` 가 들어오지 않는지 봅니다.

**글자 대비는 건드리지 않았습니다.** 비침은 칸의 배경일 뿐이고, 그 위의 점은
자기 배경(`dot_background`)을 갖고 있어 글자가 얹히는 바닥이 달라지지 않습니다.
9장의 합성 대비 문제가 생기는 자리가 아닙니다.

**오늘 칸과 지연 점** — 오늘 칸의 파란 테두리는 `inset box-shadow` 라 배경
위에 그려지고, 지연 점은 자기 배경을 갖고 있어 덮이지 않습니다. 비침은
`background` 만 건드리고 `box-shadow`·`border` 를 손대지 않습니다
(`test_t_06` 이 그 선언을 봅니다).

## 4. 기간 값을 점에 어떻게 실었는가

`calendar.dot_of()` 에 `start` 를 더해 **구조가 실어 보냅니다.**

```html
<a class="cal-dot" data-run="64" data-start="2026-10-13" data-end="2026-10-18" …>
```

화면은 계산하지도, 서버에 다시 묻지도 않습니다 — `showSpan()` 안에 `fetch` 가
없다는 것을 `test_t_04` 가 확인합니다. 시작일이 없으면 마감일 하루짜리로
채워 보내므로(`start = start_date or end_date`) 화면에 빈 값이 가지 않습니다.

**행사는 문서에 하나만 겁니다** (`document` 의 `mouseover`/`mouseout`).
점마다 따로 걸면 `외 N건` 안에서 나중에 펼쳐지거나, 날짜가 바뀌어 다시 놓인
점이 빠집니다 — 지난 라운드에 점을 옮기는 코드를 넣었으므로 실제로 생기는 일입니다.

## 5. 왼쪽 목록 배경 (11번)

`.lc` 는 원래 `background:var(--paper)` 로 불투명했습니다. 문제는 호버가
그것을 **반투명한 `--hover` 로 바꿔치기**한 것이었습니다 — `background`
단축 속성이 배경색까지 다시 정하기 때문입니다.

같은 토큰을 **불투명한 바닥 위에 얹도록** 바꿨습니다. 새 색을 만들지 않았습니다.

```css
.row.main .lc:hover,.row.sub .lc:hover{
  background:linear-gradient(var(--hover),var(--hover)),var(--paper)}
```

같은 모양이던 세 자리(`.row.team .lc:hover` · `.row.hl>.lc` ·
`.row.anchorrow>.lc`)도 함께 고쳤습니다.

**계산된 스타일로 확인했습니다** (10장 — 규칙이 있다는 것만으로는 뒤엣것이
이기는지 알 수 없습니다).

| 선택자 | 계산된 배경색 | 불투명 |
|---|---|---|
| `.row.main .lc:hover` | `rgb(255,255,255)` | O |
| `.row.team .lc:hover` | `rgb(247,247,245)` | O |

`:hover` 는 스크립트로 켤 수 없어 **그 규칙의 선언을 그대로 떠서 탐침 요소에
얹어** 쟀습니다. `drawer.js` 에도 항목을 더해 매번 보게 했습니다
(`왼쪽 라벨 열이 불투명 (평소 O · 강조 O)`).

**겹침 순서는 원래 맞았습니다** — `.lc` 가 z-index 20 이고 선택된 바가 9,
연결된 바가 8, 끄는 바가 10 입니다. 고칠 것이 없어 시험으로만 못박았습니다.
