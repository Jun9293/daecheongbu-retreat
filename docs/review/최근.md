## 0. 0단계 — 기간 비침이 화면에서 동작하지 않은 이유

**결론부터. 코드는 맞았고 배포도 됐습니다. 브라우저가 옛 `calendar.js` 를
쓰고 있었습니다.**

### 재현과 측정

서버가 실제로 새 코드를 주고 있는지 먼저 봤습니다.

```
$ curl -s http://127.0.0.1:8000/static/js/calendar.js | grep -c showSpan
2
$ curl -s http://127.0.0.1:8000/static/js/calendar.js | grep -c inspan
6
```

**서버는 새 코드를 주고 있었습니다.** 그다음 응답 헤더를 원본과 터널에서
각각 봤습니다.

| 어디로 | `Cache-Control` | `cf-cache-status` |
|---|---|---|
| `http://127.0.0.1:8000/static/js/calendar.js` (원본) | **없음** | — |
| `https://retreat.recba12.com/static/js/calendar.js` (터널) | **`max-age=14400`** | HIT |
| `https://retreat.recba12.com/login` (HTML) | 없음 | DYNAMIC |

**Cloudflare 가 `/static/*` 에 4시간짜리 `max-age` 를 스스로 붙입니다.**
원본은 아무 캐시 헤더도 보내지 않는데 터널을 지나면서 붙습니다.
HTML 은 `DYNAMIC` 이라 매번 새로 갑니다.

### 그래서 어디서 끊겼나

주소가 `calendar.js?v=1` 로 **고정**이라 브라우저에게는 4시간 동안 같은
파일입니다. `max-age` 안에서는 **서버에 물어보지도 않습니다** — 그래서
`Ctrl+Shift+R` 이 듣지 않은 것도 설명됩니다(HTML 만 새로 받고 스크립트는
메모리/디스크 캐시에서 그대로 나옵니다).

끊긴 자리는 셋 중 **첫 번째**입니다.

| 물음 | 답 |
|---|---|
| 점이 `data-start` 를 들고 있는가 | **들고 있었습니다** (새 HTML 이므로) |
| `.inspan` CSS 규칙이 실렸는가 | **안 실렸습니다** — `retreat.css?v=47` 도 같은 이유로 옛것 |
| 클래스가 붙는가 | **안 붙습니다** — 옛 `calendar.js` 에는 `showSpan` 자체가 없습니다 |
| 붙는데 안 보이는가 | 해당 없음 |

**새 HTML + 옛 JS/CSS** 라는 짝이 만들어졌습니다. 사용자에게는
"사이드바는 새로 나오는데 기능만 없는" 것으로 보였고, 그래서 "기능이
안 만들어진 것" 으로 읽혔습니다.

### 시험이 왜 못 잡았나

세 가지가 겹쳤습니다. **셋 다 "디스크의 파일" 만 보고 "브라우저가 받는
주소" 는 아무도 안 봤습니다.**

- `test_t_04` · `test_t_05` 는 pytest 라 파일을 **디스크에서 직접 읽습니다.**
  디스크의 `calendar.js` 에는 `showSpan` 이 있으므로 초록입니다
- `docs/checks/drawer.js` 는 브라우저에서 도는데, 제가 그 점검 스크립트를
  `?t=Date.now()` 로 **캐시를 피해서** 불렀습니다. 그리고 제 브라우저는
  그 세션에서 이미 새 자산을 받은 뒤였습니다
- **파일이 바뀌면 주소도 바뀌는지 보는 시험이 하나도 없었습니다.**
  `?v=` 는 사람이 손으로 올리는 값이라 시험할 대상이라는 생각을 못 했습니다

1단계가 정확히 이것을 고칩니다. 그리고 `test_u_01` 이 그 시험입니다 —
파일 내용을 바꾸면 주소가 바뀌는지 실제로 바꿔 보고 확인합니다.

## 1. 무엇을 했나

### 1단계 — 정적 주소를 내용에서 뽑는다

`app/templating.py` 에 `static()` 을 두고 템플릿 전역으로 붙였습니다.
파일 내용의 md5 앞 8자를 붙입니다.

```python
def static(path: str) -> str:
    """`/static/<path>` + 내용에서 뽑은 번호."""
    stamp = _static_stamps.get(path)
    if stamp is None or templates.env.auto_reload:
        ...
        stamp = hashlib.md5(data).hexdigest()[:8]
    return f"/static/{path}?v={stamp}"
```

운영에서는 켤 때 한 번만 재고 캐시합니다(템플릿을 켤 때 한 번만 읽는
11-2 와 같은 자리입니다 — **고친 것을 반영하려면 서버를 다시 켭니다**).
개발 서버는 `auto_reload` 가 켜져 있으므로 매번 다시 잽니다.

**왜 이렇게 하는지**를 코드에 적었습니다 — 다음 사람이 `?v=1` 로
되돌리지 않도록, Cloudflare 가 4시간을 붙인다는 사실과 함께.

#### 어느 파일들이 `?v=` 고정이었나

**9개 템플릿 전부**입니다. 손으로 올리던 번호가 파일마다 제각각이었습니다.

| 템플릿 | 고정돼 있던 것 |
|---|---|
| `base.html` | `css/app.css?v=6` · `js/flash.js?v=2` · `js/app.js?v=9` |
| `retreat_base.html` | `css/retreat.css?v=47` · `js/flash.js?v=2` · `js/sidenav.js?v=3` |
| `board.html` | `js/drawer.js?v=6` · `js/board.js?v=30` |
| `calendar.html` | **`js/drawer.js?v=1` · `js/calendar.js?v=1`** ← 한 번도 안 올렸습니다 |
| `board_add.html` · `draft.html` · `library.html` · `live.html` · `setup.html` | 각각 `?v=N` |

`board.js` 는 30까지 올렸는데 `calendar.js` 는 1이었습니다. **손으로 올리는
방식은 새로 생긴 화면에서 반드시 빠집니다.**

지금은 전부 `{{ static('js/calendar.js') }}` 입니다. 브라우저에서 확인한 값:

### 2단계 — 사이드바 계층

`준비 단계` 를 회색 묶음 제목(`.navlabel`)에서 **항목 수준**(`.navgroup`)으로
올리고, `보드`·`달력` 을 그 아래 `a.sub` 로 들여썼습니다.

**`준비 단계` 자체는 누를 수 없게 했습니다** (`<div>`, `cursor:default`).
이유:

- **보드로 보내면 `보드` 항목과 같은 일을 하는 것이 두 자리에 생깁니다.**
  이 문서가 반복해서 피해 온 모양입니다(하단 `논의 추가` 를 없앤 4-9,
  `파일 첨부` 버튼을 없앤 4-9)
- **접었다 펴기는 여기서 값을 치르지 않습니다.** 아래에 둘뿐이고, 접어서
  아끼는 세로 공간이 24px 입니다. 대신 기억할 상태가 하나 늘고
  (`sidepin` 처럼 기기에 남길지도 정해야 하고), 처음 온 사람은 접힌 채로
  만나면 `보드` 로 가는 길을 못 찾습니다
- 그래서 **묶음의 이름일 뿐**입니다. 누르는 것은 아래 둘입니다

`실무`·`회차 준비` 의 회색 묶음 제목은 그대로 뒀습니다. 브라우저에서 잰 값:

| | 글자 | 색 | 들여쓰기 |
|---|---|---|---|
| `수련회 진행` (항목) | 13.5px | `rgb(120,119,116)` = `--ink-2` | 8px |
| **`준비 단계`** | **13.5px** | **`rgb(120,119,116)`** | **8px** |
| `실무` (회색 묶음) | 11px | `rgb(155,154,151)` = `--ink-3` | — |
| `보드` · `달력` (하위) | 13px | — | **22px** |

**보고 있는 화면 표시는 하위 항목에 붙습니다** — `/calendar` 에서
`달력` 만 `aria-current="page"` 이고 `box-shadow: rgb(120,119,116) 2px 0 0 inset`
(왼쪽 2px 세로선)이 붙습니다. 안 보고 있는 하위에는 1px 헤어라인만 있어
계단이 보입니다.

### 3단계 — 화면 전환

**무엇이 그렇게 만들고 있었나** — `sidenav.js` 가 저장된 고정 여부를
**그린 뒤에** 붙였습니다.

```js
// 옛 코드 (sidenav.js 끝)
if (saved === "1") setPinned(true);
```

`body { transition: padding-left .18s }` 와 `.sidenav { transition: transform .18s }`
가 걸려 있으므로, 화면을 옮길 때마다 **사이드바가 260px 을 밀고 들어오고
본문이 그만큼 밀렸습니다.** 매번 그랬습니다. 고정을 쓰는 사람에게는 모든
이동에 붙습니다.

**무엇으로 줄였나** — 셋입니다.

1. 저장값을 **첫 그림 전에** 붙입니다. `retreat_base.html` 의 짧은 인라인
   스크립트가 `<body class="booting">` 상태에서 `sidepin` 을 답니다.
   `body.booting` 은 모든 `transition` 을 끄고, 두 번의
   `requestAnimationFrame` 뒤에 풀립니다 — 그린 뒤에 전환이 살아나므로
   **처음 자리잡는 것에는 전환이 안 붙고, 사람이 토글을 누른 것에는 붙습니다**
2. 화면 전체에는 **불투명도만** 겁니다 — `body { animation: dcb-in .12s ease-out }`,
   `@keyframes dcb-in { from{opacity:0} to{opacity:1} }`.
   밀려 들어오거나 커지는 것 없습니다 (4-0 의 조용한 기조)
3. `@media (prefers-reduced-motion: reduce)` 에서 `transition`·`animation` 을
   전부 끕니다

브라우저에서 잰 값: `animationName: "dcb-in"` · `animationDuration: "0.12s"`.
`sidenav.js` 는 이제 `aria-pressed` 만 맞춥니다.

### 5단계 — 점이 들고 있는 것을 한 자리에서

**무엇을 한 함수로 묶었나** — `reload(dot, p)` 입니다.

```js
function reload(dot, p) {
  paint(dot, p);                                   // 색
  if (p.start) { dot.dataset.start = p.start; dot.dataset.end = p.end || p.start; }
  else { delete dot.dataset.start; delete dot.dataset.end; }
  retitle(dot, p);                                 // 말
}
```

`applyStatus` 와 `applyDates` 둘 다 `paint()` 가 아니라 `reload()` 를
부릅니다. **점이 들고 있는 것(색·기간·말)이 한 자리에서 갈아 끼워집니다.**
두 줄 더하고 끝냈으면 네 번째로 같은 모양이 났을 것입니다.

**`title` 의 기준은 `retitle()`(자바스크립트) 로 정했습니다.** 이유:

- 서버 매크로는 **첫 그림만** 그립니다. 옮기고 나면 서버에 다시 묻지 않으므로
  (묻는 순간 보던 달을 잃습니다 — 4-13) **매크로는 갱신할 방법이 없습니다**
- 재료(`data-department` · `data-assignee`)를 점이 이미 들고 있고, 바뀌는
  것(상태·기간·기한 초과)은 `/dates`·`/status` 응답이 그대로 줍니다
- 그래서 **매크로는 첫 그림, `retitle` 은 그 뒤 전부** 로 나누고, 두 곳이
  같은 순서·같은 구분자(` · `)를 쓰도록 맞췄습니다.
  `test_u_12` 가 두 곳의 모양이 같은지 봅니다

**시험은 옮긴 뒤의 값을 봅니다** — `test_u_11` 은 `/dates` 를 실제로 호출한
뒤 응답의 `start`·`end` 를 보고, `test_u_14` 는 `test_u_11` 이 옮기기 전만
보고 끝내지 않는지(호출 뒤 단언이 있는지) 소스에서 확인합니다.

## 8. 판단이 들어간 자리 (발췌)

### 시험 두 개가 새 구조를 몰라 빨개졌던 것

전부 돌렸을 때 셋이 실패했고, **셋 다 이번 변경이 옳아서 난 실패**였습니다.

**(1) `tests/test_live.py::test_p33b` · `test_p33c`**

```
AssertionError: assert ['js'] == []
```

`template_reads()` 가 Jinja 식 안에서 `live.a.b` 꼴을 찾는데,
`{{ static('js/live.js') }}` 가 들어오면서 **`live.js` 를 "`live` 의 `js` 를
읽는다" 로 잡았습니다.** 문자열 안의 점은 값이 아니라 파일 이름입니다.

```python
inside = " ".join(a or b for a, b in JINJA.findall(text))
inside = re.sub(r"'[^']*'|\"[^\"]*\"", " ", inside)   # ← 더함
```

**(2) `tests/test_ui_shift.py::test_03`**

```python
assert 'saved === "1"' in js
```

3단계에서 그 줄을 `sidenav.js` 밖으로(첫 그림 전의 인라인 스크립트로)
일부러 옮겼습니다. 시험을 **새 자리를 보도록** 바꿨습니다 —
그리고 옛 자리로 돌아가지 않는지도 함께 봅니다.

```python
shell = (ROOT / "app" / "templates" / "retreat_base.html").read_text(encoding="utf-8")
assert "localStorage.getItem('dcb.sidepin')" in shell
assert 'saved === "1"' not in js, "아직 그린 뒤에 붙인다"
```

### `static()` 을 켤 때 한 번만 재는 이유

요청마다 해시를 다시 뜨면 화면 하나에 파일 5개 × 요청 수만큼 디스크를
읽습니다. 운영은 어차피 **템플릿도 켤 때 한 번만 읽습니다**(11-2) —
둘이 함께 낡으므로 어긋나지 않습니다. 개발 서버는 `auto_reload` 가
켜져 있어 매번 다시 잽니다.

### `body.booting` 을 왜 두 번의 `requestAnimationFrame` 뒤에 푸는가

한 번으로는 스타일이 아직 적용되기 전에 풀려서 전환이 살아납니다.
두 번째 프레임이면 첫 그림이 끝난 뒤입니다. 그래서
**처음 자리잡는 것에는 전환이 안 붙고, 사람이 토글을 누른 것에는 붙습니다** —
전환을 아예 없앤 것이 아니라 **자리잡기와 조작을 갈랐습니다.**
