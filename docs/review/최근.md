## 무엇을 했나

**바꾼 곳은 화면뿐입니다. 고르는 방식은 건드리지 않았습니다** — 지금 성적표를
채우려는 참이라, 제안이 달라지면 표본을 다시 잡아야 하기 때문입니다.

| 단계 | 무엇 |
|---|---|

| 2 | 누르기 전에 **남을 문장**을 볼 수 있게. 이미 있으면 그렇다고 말함 |
| 3 | 본문에 새던 `<span color=…>` · `{color=…}` · `<details>` 를 걷어냄 |
| 4 | 다시 넣고 **제안이 달라졌는지** 다시 셈 |

## 1단계 — 브라우저에서 본 것 그대로

**pytest 는 화면을 못 봅니다** (10장). 아래는 개발 서버(포트 8003)의
`/meetings/<id>` 를 실제로 열어 DOM 에서 읽은 문구입니다.

### 바꾸기 전

```
PPT 템플릿 제작
회의록과 업무 이름에 '템플릿, PPT, 제작' 이(가) 함께 나옵니다 (겹친 낱말 3개)
                                                      [ 이 업무에 남기기 ]
```

업무 이름이 제목처럼 서 있고 그 아래가 근거뿐입니다. **무엇을 하자는
것인지가 어디에도 없습니다.**

### 바꾼 뒤

```
하려는 일 : 이 회의 내용을 「PPT 템플릿 제작」 의 논의로 남깁니다
근거      : 회의록과 업무 이름에 '템플릿, PPT, 제작' 이(가) 함께 나옵니다 (겹친 낱말 3개)
출처      : 2026-05-24 회의록
            ▸ 남을 내용 보기                             [ 남기기 ]
```

- 하려는 일 `.mt-do` 14px `--ink` · 근거 `.mt-sug-why` 12.5px `--ink-2` ·
  출처 `.mt-sug-from` 11.5px `--ink-3`
- **어느 회의에서 온 것인지가 제안마다** 붙습니다. 전에는 위쪽 제목에만
  있었습니다
- 느낌표도 권유도 없습니다 (4-0 — 조용하게)

### 새 업무 제안

```
[새 업무로 만들기] 헤브론에게 전달
회의록에서 할 일처럼 보이는 문장입니다 — 아직 이 이름의 업무가 없습니다
2026-05-24 회의록                            보드의 + 업무 추가 에서
```

라벨(`.mt-kind`)이 앞에 붙고 나머지 모양은 같습니다. 붙일 곳이 없으므로
단추 대신 **어디서 만드는지**를 말합니다.

> **여기서 한 번 걸렸습니다.** 처음에는 화면에 이렇게 떴습니다 —
> `새 업무로 만들기⟨빨간형광펜⟩헤브론에게 전달`. 3단계에서 붙인 **우리 표시가
> 하려는 일 안으로 따라 들어온 것**입니다. `하자는말()` 에서 **화면에서만**
> 뗐습니다 — 본문에는 그대로 남고 고르는 것도 그대로입니다(떼고 나서 95·59

## 2단계 — 브라우저에서 본 것 그대로

`▸ 남을 내용 보기` 를 펼치면 이렇게 나옵니다. 회의록 본문 전체라 길어서
접어 두었습니다.

```
[회의록 2026-05-24 · 26.05.24] 에서 옮김
- ⟨빨간형광펜⟩수련회 간략광고 6/7
- 오티 - 순서 등 헤브론에 전달
  ...
```

**미리보기와 실제 저장이 `discussion_body()` 한 함수를 씁니다.** 두 벌이면
보여준 것과 남는 것이 갈리고, 갈린 쪽을 아무도 눈치채지 못합니다 — 이
프로젝트에서 가장 자주 고쳐 온 모양이라 처음부터 하나로 두었습니다.

### 이미 있으면 말합니다

같은 업무에 그 회의록에서 온 논의가 이미 있으면 —

```
이 회의 내용을 「PPT 템플릿 제작」 의 논의로 남깁니다
이 회의록에서 온 논의가 이미 있습니다. 다시 누르면 같은 내용이 두 번 남습니다.
회의록과 업무 이름에 '템플릿, PPT, 제작' 이(가) 함께 나옵니다 (겹친 낱말 3개)
2026-05-24 회의록                                    [ 그래도 남기기 ]
```

**막지는 않습니다.** 사람이 정합니다. 다만 두 번 남으면 어느 것이 맞는지
알 수 없고, 지우는 길은 그 업무의 논의 탭뿐이라 되돌리는 값이 비쌉니다.

## 3단계 — 본문의 태그

### 무엇이 얼마나 있었나 (넣기 전 원본에서 셈)

| 태그 | 곳 |
|---|---|
| `<span color="red">` | 59 |
| `<span color="yellow_bg">` | 25 |
| `{color="yellow_bg"}` | **3** ← 놓치고 있었다 |
| `<span color="red_bg">` | 19 |
| `purple_bg` · `gray` | 1 · 1 |

**노란 형광펜이 노션에 두 가지 모양으로 적혀 있었습니다.** 하나만 처리하고
있었더니 위쪽 안내문은 `⟨형광펜⟩` 을 설명하는데 본문에는
`{color="yellow_bg"}` 가 남아 **안내문과 본문이 어긋났습니다.**

### 빨간 형광펜 — 합치지 않았습니다

`red_bg` 가 19곳입니다. 쓰인 것을 보면 —

| 본문 | 무엇으로 보이나 |
|---|---|
| `면장갑` | 라텍스에서 바꾼 **결정** |
| `수련회 간략광고 6/7` | **날짜** |
| `아날로그 예배라서 주보광고로 진행` | **방식** |

결정처럼 보이는 것도 있고 그냥 눈에 띄게 칠한 것도 있습니다.
**노란 것과 뜻이 같은지 다른지 모릅니다.**

**모르면 합치지 않습니다.** 합치면 두 색이 같은 뜻이었다는 주장이 되고,
그 주장은 아무도 한 적이 없습니다. `⟨빨간형광펜⟩` 으로 따로 적어 **원본의
구별을 그대로 지킵니다** (6-9). 뜻이 밝혀지면 그때 정합니다.

### 걷어낸 뒤

```
본문에 남은 태그: []      ← <span · </span · {color= · <details · <summary 전부 없음
⟨형광펜⟩     24곳
⟨빨간형광펜⟩ 19곳
본문 첫 줄   "- ⟨빨간형광펜⟩수련회 간략광고 6/7"
```

`<details>` · `<summary>` 도 벗겼습니다 — 들여쓰기가 이미 구조를 말해 줍니다.

## 4단계 — 다시 넣고 다시 셈 (기준 10)

### 절차

```

    --retreat "2026 여름수련회 Belong" --undo 성적표

```

> **성적표 문서(`docs/review/제안-성적표.md`)에는 아직 못 적었습니다.**
> 파일이 편집기에서 열려 있어(`~$제안-성적표.md`) 쓰기가 거절됐습니다.
> **채우는 중일 수 있어 덮어쓰지 않았습니다** — 닫으신 뒤에 넣겠습니다.
> 위 두 명령이 그때 넣을 내용 전부입니다.

### 제안이 달라졌나 — **안 달라졌습니다**

| | 태그 있을 때 | 걷어낸 뒤 |
|---|---|---|
| 논의 제안 | 95 | **95** |
| 새 업무 제안 | 59 | **59** |

표본 네 회의도 그대로입니다 — 03.29 `1·1` · 05.24 `5·5` · 07.05 `3·0` ·
08.09 `3·2` = **논의 12 · 새 업무 8 · 합계 20.** 성적표와 맞습니다.
**표를 고칠 것이 없습니다.**

**왜 안 달라졌나** — 지시문은 "`span`·`color`·`red_bg` 가 낱말로 세어진다"
고 짚었고 그것은 맞습니다. 그런데 세어져도 **업무 이름과 하나도 안 겹칩니다.**

```
보드 업무 이름에 든 영문 낱말: ['GBS', 'PPT']
태그에서 나온 낱말과 겹치는 것: 없음
```

겹침이 0이면 점수에 더해지지 않습니다. **태그는 읽기 문제였지 고르기 문제는
아니었습니다.** 그래도 걷어낸 것은 사람이 읽을 수 없었기 때문이고, 업무
이름에 영문이 늘면 그때는 고르기 문제가 되기 때문입니다.

## 판단이 들어간 자리

### ① 빨간 형광펜을 노란 것과 합치지 않았다

위 3단계에 근거를 적었습니다. **합치면 두 색이 같은 뜻이었다는 주장이 되고
그 주장은 아무도 한 적이 없습니다.** 표시가 둘로 늘어 본문이 조금 시끄럽지만,
원본에 있던 구별을 우리가 지우는 것보다 낫다고 봤습니다 (6-9).

### ② 우리 표시를 화면에서만 뗀다

`⟨빨간형광펜⟩` 이 새 업무 제안의 "하려는 일" 안으로 따라 들어왔습니다.
본문에서 빼면 원본의 사실이 사라지고, 그대로 두면 하려는 일을 읽는 데
방해가 됩니다. **본문에는 남기고 화면에서만 뗐습니다.** 고르는 것에는
닿지 않는지 다시 세어 확인했습니다 (95·59 그대로).

### ③ 이미 있어도 막지 않는다

같은 회의록에서 온 논의가 이미 있으면 **말하되 막지 않습니다.** 단추가
`그래도 남기기` 로 바뀝니다. 회의가 이어지면서 같은 회의록을 나눠 남기는
경우가 있을 수 있는데, 그것을 기계가 판단할 수 없습니다.

### ④ 성적표에 절차를 못 적었다

파일이 열려 있어 쓰지 못했습니다. **강제로 덮어쓰지 않았습니다** — 사람이
채우는 중일 수 있고, 덮으면 그 작업이 사라집니다. 넣을 내용은 위 4단계에
그대로 있습니다.
