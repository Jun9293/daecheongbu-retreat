# 1. 확인 — 제목을 글자 그대로 견줌 (0a · 0b)

**다른 까닭 (짐작 · 고치지 않았다)**

- 파일 이름은 내보낼 때 사람이 **순서 번호를 붙이고 줄여 지은 이름**이다 — 번호 · 빈칸 · 끝의 「회의록」 을 떼면 **8 이 페이지 제목과 글자가 같고**, 남은 2 는 파일 이름 글자가 제목 안에 **순서대로 다 들어 있다**(줄인 이름)
- 회의 제목은 페이지 제목이 아니라 **페이지 안의 날짜 머리**다 — `scripts/import_meetings.py` 가 한 페이지를 날짜마다 잘라 그 머리를 제목으로 넣었다(`title=m.heading`). 50 중 48 이 숫자로 시작한다
- 그래서 「제목이 같은가」 는 이 자료에서 짝의 근거가 못 되고, 짝은 2장의 규칙(파일 이름 줄기 ↔ 페이지 제목 줄기)으로 정했다

**1판을 바로잡을 것 하나** — 1판 5장이 「노션 업무 DB 속성 목록에 `관련 팀` 이 없다」 고 적었는데 틀렸다. 페이지를 열어 보면 속성에 있다(1판이 속성 목록을 뽑다 놓쳤다). CLAUDE.md 13장은 맞았고, 인계의 그 줄에 「2판에서 틀린 것으로 확인」 을 덧붙였다.

# 2. 외부 id 칸 (1a · 1b)

- **`meetings.notion_page_id`** · `VARCHAR(36)` · NULL — 모델(`app/models.py` 의 `Meeting`)과 `app/db.py` 의 `_ADDED_COLUMNS` 한 줄
- **부팅은 칸만 붙이고 값을 안 채운다** — `_ADDED_COLUMNS` 는 NULL 칸이라 11-2 의 「칸 붙이기」 쪽이다. 채우는 곳은 스크립트 하나(`test54_a01` 이 `app/` 에 그 칸을 쓰는 곳이 없음을 잰다)

# 3. 전환 `scripts/회의록id달기.py` (2a–2d)

- 다른 전환과 같은 꼴 — 기본 미리보기 · `--실행` · 채울 것이 있을 때만 직전 `VACUUM INTO` 사본(`재정들여오기.사본을_뜬다` — 세션이 여는 파일과 사본 뜰 파일이 다르면 멈춤) · 채운 뒤 commit 전에 DB 를 다시 셈(id 달린 수 · 채운 행마다 id · 노션이 아닌 회의가 그대로인지)
- **짝** — 파일 이름에서 앞 번호를 떼고 페이지 제목에서 빈칸과 끝의 「회의록」 을 뗀 것이 ① 글자 같으면 짝 ② 남은 것끼리는 파일 이름 글자가 제목에 순서대로 다 든 페이지가 **하나일 때만** 짝. 둘 이상이거나 없으면 멈춘다
- **대상** — origin 이 노션이고 출처가 그 파일인 회의 전부(한 파일이 여럿으로 잘렸으면 그 여럿 전부에 같은 id)
- **안 건드림** — 노션이 아닌 회의(앱에서 만든 3). 같은 id 가 있으면 건너뛰고, **다른 id 가 있으면 덮지 않고 멈춘다**
- 두 번째 실행은 「채울 것이 없습니다」
- 값은 안 찍는다 — 건수만
