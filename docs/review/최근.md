## 판단이 들어간 자리

### ① 논의 12 를 13 으로 고쳤다

표본을 정할 때 센 것과 채워 보니 나온 것이 하나 달랐습니다. **20 을 맞추려고

성적표의 표본 표도 13 으로 고쳤고, 왜 고쳤는지를 그 자리에 적었습니다.

### ② 지운 시험 자리에 주석을 남겼다

시험을 지우면 아무 흔적도 안 남습니다. 그런데 이 시험은 **일부러 얼려 둔
것**이라, 다음에 `suggest.py` 를 고치는 사람이 "여기 손대면 안 되나" 를
물을 자리가 필요합니다. 지운 이유와 함께 남겼습니다.

### ③ 배터리 설정을 끄지 않았다

`DisallowStartIfOnBatteries` 를 끄면 재시작이 바로 됩니다. **끄지
않았습니다** — 그 설정은 "콘센트에 안 꽂혀 있다" 를 알려 주는 신호이기도
해서, 끄면 배터리로 며칠 돌다가 어느 날 서버가 통째로 사라지는 쪽으로
갑니다. 대신 이번만 손으로 띄우고, **증상과 절차를 배포 안내에 적었습니다.**

### ④ 로드맵에 성적을 숫자로 적었다

12장의 회의록 항목이 "만들 것" 으로만 남아 있으면 다음 사람이 지금 방식이

## 재시작과 확인 (11-3 2단계)

12-1 을 그대로 돌렸더니 이렇게 나왔습니다.

```
멈추기 전 PID:
포트가 비었습니다
다시 켠 뒤 PID:
실패 — 다시 뜨지 않았습니다. data\server.log 를 보세요
```

**앱이 잘못된 것이 아니었습니다.** `server.log` 에 오류가 하나도 없고
(마지막 줄이 사람의 `/meetings/46/suggestions` 200), `import app.main` 도
됩니다. 작업 스케줄러가 **아예 안 띄운 것**이었습니다.

```
(Get-ScheduledTask -TaskName '대청부 앱').State        -> Queued   (Running 이 아님)
.Settings.DisallowStartIfOnBatteries                  -> True
Get-CimInstance Win32_Battery .BatteryStatus          -> 1 (방전 중) · 94%
```

**노트북이 배터리로 돌고 있어서** 작업이 `대기 중` 에 머물고 영영 시작되지
않습니다. `Stop-ScheduledTask` → `Start-ScheduledTask` 를 다시 해도 같습니다.

**설정은 건드리지 않았습니다.** 이 설정은 "콘센트에 안 꽂혀 있다" 를 알려
주는 신호이기도 해서, 끄면 어느 날 배터리가 떨어져 서버가 통째로 사라지는
쪽으로 갑니다. 대신 **손으로 띄웠습니다.**

```
Start-Process -FilePath "...\scripts\serve.bat" -WindowStyle Hidden
올라왔습니다 — PID: 25644
```

**돌고 있는 서버에서 받아 봤습니다.**

```
GET /static/js/meeting.<해시>.js   -> 200 · 5429 bytes
GET /static/css/retreat.<해시>.css -> 200 · 96543 bytes
GET /meetings                      -> 302 -> /login
```

해시는 로컬 파일 내용에서 계산한 것입니다. **이번 라운드는 앱 코드를 하나도
안 고쳤으므로**(시험과 문서만) 해시가 지난 라운드와 같고, 그 주소가 200 인
것은 서버가 지금 파일을 들고 있다는 뜻입니다.

> **충전기를 꽂으면 12-1 로 다시 정리하세요.** 지금은 스케줄러가 아니라
> 손으로 띄운 프로세스라, 컴퓨터를 껐다 켜면 `시작 시` 트리거로 다시
> 스케줄러가 맡습니다(그때도 배터리면 또 안 뜹니다).
> 이 증상과 절차를 `docs/배포-안내.md` **12-2-1** 로 적어 두었습니다.
