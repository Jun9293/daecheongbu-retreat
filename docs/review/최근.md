## 3. 2단계 — 보드 첫 렌더는 **안 지나고 있었습니다**

지적하신 그대로입니다. 최근.md 의 전/후 표에 `보드 첫 렌더` 가 없었던 이유가
그것이었습니다 — 그 줄을 안 적은 게 아니라 **안 고쳤습니다.**

`board.build()` 안의 `make_row()` 가 `bar_style()` 을 직접 부르고 있었고,
모바일 묶음의 테두리도 따로 부르고 있었습니다. `paint_of` 는 `/status` 와
`/dates` 만 쓰는 상태였으니 **첫 렌더가 세 번째 길로 남아 있었습니다.**

이제 `bar_style` 을 부르는 곳은 **`paint_of` 안의 두 번뿐**입니다.

| | 전 | 후 |
|---|---|---|
| 보드 첫 렌더 (`make_row`) | **`bar_style` 직접** | `paint_of(run, today, ghost=ghost)` |
| 보드 모바일 묶음 테두리 | **`bar_style` 직접** | `paint_of(r, today)["bar_border"]` |
| 보드 `/status` · `/dates` | `paint_of` | `paint_of` |
| 달력 첫 렌더 (`dot_of`) | `paint_of` | `paint_of` |

지나게 하려고 둘을 더했습니다.

- `paint_of(..., *, ghost=False)` — 고스트 바는 색이 없고 점선 테두리만 씁니다
- `NO_DEPARTMENT_COLOR = "#69726D"` — 부서 없는 업무의 색이 세 군데에 흩어져
  있었습니다

> **한 가지가 바뀝니다.** 부서가 **아예 없는** 업무의 달력 점 색이
> `#787774` 에서 `#69726D` 로 옮겨갑니다. 한 곳으로 모으면 기본값도 하나여야
> 하고, 보드가 세 자리에서 쓰던 값이자 `Department.color` 자신의 기본값이라
> 그쪽으로 맞췄습니다. 둘 다 회색이라 눈에 띄지 않고, 부서가 있는 업무는
> 영향이 없습니다.

## 4. 3단계 — 시험은 **이미 상대 계산**이었습니다

`test_r2_01` · `test_r2_02` 는 처음부터 `dt.date.today() ± timedelta` 로
날짜를 만듭니다. 고정 날짜가 아니므로 **날이 바뀌어도 뒤집히지 않습니다.**
그래서 지시하신 두 갈래(상대 계산으로 바꾸기 / 라우터를 열기) 중 **아무것도
하지 않는 쪽**을 골랐습니다.

`board.py` 라우터가 `dt.date.today()` 를 직접 부르는 것은 그대로 두었습니다.

- 그 자리는 **조립 지점**입니다. `board.build()` 도 `calendar.build()` 도
  `paint_of()` 도 전부 `today` 를 인자로 받고 있고, 실행 날짜를 정하는 것은
  라우터 한 곳뿐입니다 — 주입해야 할 곳은 이미 다 주입돼 있습니다
- 라우터에 `today` 를 열면 **주소로 오늘을 바꿀 수 있게** 됩니다. 기한 초과
  판정이 걸린 값이라 그건 열 이유가 없습니다
- 지금 시험 중에 이것 때문에 실패하는 것이 하나도 없습니다. 없는 문제를
  고치면서 문을 하나 여는 셈이 됩니다

바꾸지 않았다는 것을 시험으로 못박지도 않았습니다 — 그건 "이렇게 두자" 는
결정이지 지켜야 할 규칙이 아닙니다.

## 5. 4단계 — `code_only` 는 **멀쩡하지 않았습니다**

지적하신 그대로 잘랐습니다.

```
"const u = 'https://x'; // 설명"   →   "const u = 'https:"
```

`drawer.js` 에 정말로 그런 줄이 있습니다 — `NOT_A_URL` 안내 문구와
`URL_RE` 정규식입니다. 다만 `code_only` 를 지금까지 **`calendar.js` 에만**
썼고 거기엔 문자열 속 `//` 가 없어서, 조용히 통과한 시험은 없었습니다.
운이 좋았던 것이지 안전했던 것이 아닙니다.

고치는 데 한 번 더 걸렸습니다. 따옴표만 따라가게 했더니 `esc()` 의
`/[&<>"]/g` **정규식 안의 `"`** 를 문자열 시작으로 읽어서, 그 뒤가 통째로
문자열이 되어 파일의 절반이 사라졌습니다(`NOT_A_URL` 이 그래서 안 잡혔습니다).
그래서 정규식 리터럴까지 따라갑니다 — 정규식인지 나눗셈인지는 앞 글자로
가릅니다. 자바스크립트를 제대로 해석하는 것이 아니라 **이 저장소의 코드에서
틀리지 않을 만큼**이고, 그렇게 적어 두었습니다.

`test_s_06b` 가 실제 `drawer.js` 를 걸어 두어, 다음에 또 반쪽이 되면 잡습니다.

**있음을 확인하는 쪽으로 옮긴 것** — `test_r2_03` 은 없음(`todayIso` ·
