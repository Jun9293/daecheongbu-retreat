## 1. 회의 항목 → 할 일이 보이게 (지시문 1번)

- **`/meetings/items/{id}/to-task` 가 TaskRun 을 만든다** — 보드의
  「새로 만들기」(`/board/add/new`)와 같은 모양: TaskLibrary(main ·
  origin history · 부서는 **키**로) + TaskRun(run_no max+1 ·
  relink_prerequisites) · 날짜는 `relative_position` 으로 상대 위치 저장
- **날짜 = 항목의 마감일 하나** (시작=마감 — 달력의 점과 같은 뜻, 4-13).
  마감이 없으면 **둘 다 비운다** — 달력의 「날짜 없는 업무」 로 모여
  사람이 정한다. 지어내지 않는다 (`test11_t02`)
- **출처** — `TaskRun.source_meeting_id` (8장에 적음). 항목 쪽에는
  `converted_run_id` 가 남고, `converted_task_id` 는 남기되 새로 쓰지
  않는다 (0장)
- **만든 뒤 그 업무의 드로어로 간다** — 303 Location 이
  `/tasks?task=<run_id>` (`test11_t01`). 담당자 알림의 링크도 같은 주소
- **옛 Task 로 이미 전환된 항목은 새로 만들지 않는다** — 만들면 같은
  항목의 할 일이 둘이 된다. 「목록에는 안 보인다」 를 말하고 돌아간다
  (`test11_t03`)
- 스키마: `task_runs.source_meeting_id` · `meeting_items.converted_run_id`
  를 `_ADDED_COLUMNS` 로 — 운영 DB 에 붙은 것 확인(아래 운영 반영)
- 1-f: 게이트 제외칸의 tasks 두 칸 문구를 사실로 —
  「이제 seed 만 쓴다; 할 일 전환은 TaskRun 을 만든다」, related 근거를
  죽는 줄(meetings.py:225) 대신 `seed.py:230` 으로

## 2. 번호 마무리 (지시문 2번)

- 2-a **원표기 보존은 지난 판 검토 반영으로 이미 코드에 있었다**

  변형으로(3-4-4 는 가명의 3-4-4 로), 가명 쪽 변형 수가 다르면

## 7. 판단이 들어간 자리 (발췌)

- **권한은 안 옮겼다** — 전환 라우트는 기존 `require_editor` 그대로.
  `/board/add/new` 의 부서 편집 검사(can_edit_department_by_key)를
  옮기면, 부서가 비어 있는 회의 항목(보통이 그렇다)에서 대상 키가
  None 이라 **비관리자가 전부 막힌다** — 회의 흐름이 조용히 죽는다.
  지시문이 따르라고 한 것은 「회차·부서·시작일·마감」 넷이다
- **seed.py 의 Task 생성은 남겼다** — 화면에서 닿지 않는 개발용 데모
  자료이고, 옛 표를 다루는 남은 코드(위험 점검·확인 요청)의 재료다.
  수용 기준 3의 「0곳」 은 **앱 런타임 경로 기준**으로 읽었고, 그
  경계를 `test11_g01` 독스트링에 적었다 — 0-a 표 ①과 견줄 수 있다
- **날짜 없으면 비운다** — 마감 없는 항목에 회의 날짜를 박으면 만들자마자
  기한 초과로 읽힌다. 날짜 없는 업무는 달력이 이미 다루는 모양이다(4-13)
- swap 의 변형 치환 순서는 `번호변형들` 목록 순 — 변형끼리 substring
  관계가 없어(숫자형은 하이픈형 안에 없음) 겹침 손상이 없다
- `test11_p01` 은 합성 대응표를 **모듈 인스턴스의 MAP_PATH 에 물려**
  잰다 — 실제 대응표는 안 건드리고, 「대응표에 넣으면」 이라는 지시문의
  경로(load_map → 표기들/실명이있나)를 실제로 지난다
