## (a) ✗ 를 찍는 자리와 실패로 세는 자리

재는 법 — 주석을 걷어낸 뒤(줄 수는 지키고) `results.push` 에 `✗` 가
든 줄과 `errors.push(` 가 든 줄을 각각 셉니다. `tests/test_stage20.py`
의 `찍는자리`·`세는자리` 가 그 함수이고, 기준 커밋에도 같은 것을
돌렸습니다.

| | ✗ 를 찍는 줄 | 실패로 세는 줄 |
|---|---|---|
| 고치기 전 (`928afc7`) | **55** | **55** |
| 고친 뒤 | **1** | **1** |

**수는 같았지만 짝이 어긋나 있었습니다.** 지난 판 검토가 찍는데 안 세는
줄 셋(처음 열면 업무 규칙 탭 · 취소하면 폼이 닫힘 · 다시 분석 뒤 판정)을
찾아 고쳤고, 그 뒤로는 **차이 0** 입니다.

| 차이 | 지지난 판 | `928afc7` | 지금 |
|---|---|---|---|
| 찍는데 안 세는 줄 | **3** | 0 | **0** |
| 세는데 안 찍는 줄 | 0 | 0 | **0** |

> **가운데 칸을 따로 둡니다.** 첫 표의 「고치기 전」 은 `928afc7` 인데
> 둘째 표에서 같은 이름으로 3 을 적으면 **그 커밋에서 3 이 나온다**로
> 읽힙니다 — 다시 재면 0 입니다(검토가 짚었습니다). 3 은 지난 판
> 검토가 찾기 전, 그러니까 그보다 앞선 상태의 값입니다.

> **수가 같다고 짝이 맞는 것이 아닙니다.** 55 대 55 인 채로 셋이
> 어긋나 있었습니다 — 「몇 개인가」 로는 안 잡히고, **길이 하나여야**
> 어긋날 자리가 없습니다. 그래서 이번 판은 수를 맞추는 대신 **길을
> 하나로 모았습니다**(1장). 지금 `✗` 를 찍는 줄과 `errors.push` 줄은
> 각각 하나이고 **둘 다 `잰다` 안**입니다.

# 1. 찍는 자리와 세는 자리를 하나로

## 1-a. `잰다` 하나

    const 잰다 = (ok, 라벨, 까닭) => {
      results.push((ok ? '✓' : '✗') + 라벨);
      if (!ok) errors.push(까닭 === undefined ? 라벨.trim() : 까닭);
      return ok;
    };

전에는 이랬습니다 — 찍는 문장과 세는 문장이 **따로**이고, 조건을 **두
번** 적었습니다.

    results.push((cond ? '✓' : '✗') + ' 라벨');
    if (!cond) errors.push('까닭');

**둘을 손으로 맞춰야 했고, 실제로 셋이 어긋나 있었습니다.** 이제 ✗ 를
찍는 길이 하나뿐이라 어긋날 자리가 없습니다. `까닭` 을 안 주면 라벨을
그대로 쓰므로 **「✗ 를 찍었는데 셀 말이 없다」** 도 생기지 않습니다.

`check()` 안의 ✗ 와 드래그 시험 앞의 ✗ 도 같은 길을 지납니다 — 예외를
하나 두면 그것이 다음 예외의 근거가 됩니다.

## 1-b. 검사가 견준다

JS 에서 배열을 진짜로 숨길 수는 없으므로, **검사가 길이 하나인지**를
잽니다 (`tests/test_stage20.py`).

| 시험 | 무엇을 |
|---|---|
| `test20_p01` | 찍는 자리도 세는 자리도 **각각 하나**이고, 서로 세 줄 안에 있다 |
| `test20_p02` | 그 하나가 `잰다` 안이고, 까닭을 안 주면 라벨을 쓴다 |
| `test20_p03` | **막는 쪽** — 옛 모양(찍기만 하고 안 세기)을 심으면 찍는 자리가 둘이 되어 걸린다 |
| `test20_p04` | ③ **부르는 쪽이 실제로 있다** — 만들어 두고 아무도 안 부르면 판정이 화면에 안 나온다 |

## 1-c. 0-(a) 의 차이

지난 판이 셋을 이미 고쳤으므로 이번에 남은 차이는 **0** 이었습니다.
「못 쟀음」 으로 내린 하나(다시 분석 뒤 판정)는 그 줄 바로 위에 이유가
적혀 있습니다 — 판정이 안 오면 위의 `check` 가 이미 「못 쟀음」 으로
내므로 여기서 또 ✗ 로 셀 일이 아닙니다.

# 2. 자가시험을 두 계정으로

| | 관리자 | 부서 리더 |
|---|---|---|
| 잰 갈래 | **6** | **5** |
| 놓친 갈래 | **0** | **0** |
| 못 심은 갈래 | **0** | **1** (제목 편집 — 그 계정에 그 자리가 없다) |
| 깨끗한 판 | 79 / 건너뜀 2 / 못 쟀음 0 | 62 / 건너뜀 15 / 못 쟀음 0 |

여섯 갈래 전부 **「✗ — 잡음」**, 못 심은 하나는 **「· 못 심음」** 입니다.
못 심은 것을 「잡았다」 로도 「놓쳤다」 로도 세지 않습니다 — **못 재는
것을 「재 봤다」 로 두지 않기 위해서**입니다.

**④ 를 고쳤습니다.** 전에는 논의 입력칸을 **숨기기만** 했는데, 부서
리더에게는 이미 숨겨져 있어 아무 일도 안 일어났습니다 — 그 갈래가 그
계정에서 한 번도 안 재졌을 것입니다. 이제 **계정을 보고 반대로** 심습니다:
고칠 수 있으면 숨기고, 못 고치면 **보이게**. 어느 쪽이든 「권한과
어긋남」 입니다.

**안 지나는 길은 0-(b) 표의 오른쪽 칸에 있고 AJ-a 에 남겼습니다.**

## 2-b. 계정은 둘로 늘렸지만 화면은 여전히 보드 하나입니다

자가시험은 **보드에서만** 돌렸습니다 — 두 판 다 깨끗한 판의 수가
5장의 `/board` 줄과 같습니다(79/2 · 62/15).

그래서 **화면마다 다른 판정 줄은 자가시험이 한 번도 안 지납니다** —
목록의 상태 칸(권한으로 갈리는 넷)과 달력의 비침이 그것입니다.
AI-a 가 약한 자리로 적어 둔 둘 중 **계정 쪽만 닫혔고 화면 쪽은
그대로**입니다. 그래서 AI-a 를 「부분 처리」 로 두고 화면 쪽을
`docs/봐둘것.md` **AJ-c** 로 떼어 냈습니다 — 라벨과 본문이 다른 것을
가리키면 닫힌 줄 알고 넘어갑니다(11-3).
