### ① 라이브러리+run 을 만드는 코드 전수 (0-a) — 무엇을 채우나 · 갈린 곳

| 자리 | 만드는 것 | 이 판 |
|---|---|---|
| `routers/board.py` add_new | lib+run (사용자 날짜) | **create_run 으로** — 라우터에는 문(부서 키 권한)과 파싱만 남음 |
| `routers/meetings.py` 전환 | lib+run (항목 마감일) | **create_run 으로** — 라우터에는 문(부서 적힌 항목의 키 검사)만 남음 |
| `domain/library.py` create_retreat (마법사) | 회차 개설의 **일괄** 생성 | **남김** — 모양이 다르다: 미선택도 included=False 로 만들고, 번호를 1부터 일괄로 매기고, 지난 논의를 실어 오고, 선행을 2패스로 잇는다. 일회성 하나 만들기와 다른 일 |
| `routers/library.py` create_library_task | **lib 만** (회차 없이) | 남김 — run 을 만들지 않는 자리 |
| `routers/board.py` add_existing | **있는 lib** → run (되살리기 포함) | 남김 — 라이브러리를 만들지 않는 자리 |
| `seed_library.py` | 초기값 시드의 lib+run | 남김 — 화면에서 닿지 않는 일회성. (`seed.py` 는 lib·run 을 만들지 않는다 — 옛 Task 데모만. 검토 반영으로 정정) |

**갈려 있던 필드 전부** (add_new ↔ 전환, 판 이전) → create_run 에서 고른 쪽:

| 갈린 것 | add_new | 전환 | create_run (더 안전한 쪽) |
|---|---|---|---|
| 제목 자르기 | 안 자름 | strip+[:200] | **strip+[:200]** — DB 가 String(200), 다른 백엔드에서 터진다 |
| 분류 검증 (TASK_KINDS · sub는 상위 필수) | 있음 | 없음 (항상 main) | **있음** |
| 마감<시작 거절 | 있음 | 없음 | **있음** |
| 날짜 없음 | 불가 (필수) | 허용 | **허용** — 달력 「날짜 없는 업무」 (4-13). 지어내지 않는다 |
| 빈 제목 거절 | 있음 | 있음 | 있음 (같았음) |
| assignee · source_meeting_id | 없음 | 있음 | **인자** — 경로가 주는 값 |
| 권한 | 부서 키 검사 | 편집자만 | **각 라우터의 문** — 이 판에서 전환도 부서 적힌 항목은 키 검사 (2번) |
| 활동기록 대상 | lib | run | 경로 몫 (남길 말이 다르다) — create_run 은 커밋·기록 안 함 |

## 9. 판단이 들어간 자리 (발췌)

- **마법사를 create_run 으로 안 옮긴 이유** — 표 ①. 일괄 생성(미선택
  included=False · 번호 일괄 · 논의 실어 오기)은 일회성 하나 만들기와
  다른 일이고, 끼워 맞추면 create_run 에 「일괄일 때만」 가지가 생긴다
- **전환 권한은 security 의 문을 그대로** — 새 검사를 만들면 U-a 가
  한 곳으로 모은 것이 다시 갈라진다. 키 없는 구설계 부서는 그 문이
  id 로 물러서는 것까지 그대로 따른다
- **apply-new 의 부서는 이름 대조** — 제안의 부서가 표시용 이름이라
  키가 없다. 못 맞추면 조용히 다른 값이 되지 않게 비우고 말한다
- **낱말판 새 업무에는 단추를 안 낸다** — title 이 없고, 회의록 문장을
  그대로 제목으로 쓰는 것은 성적표가 틀림으로 짚은 모양이다
