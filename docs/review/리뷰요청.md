## 4. 특히 봐 주셨으면 하는 것

**① 캐시 번호를 내용 해시로 바꾼 것 — 이 방식이 맞는지**

`templating.static()` 이 파일 내용의 md5 앞 8자를 붙입니다.
운영에서는 **켤 때 한 번만** 재고 캐시합니다 — 템플릿도 켤 때 한 번만
읽으므로(11-2) 둘이 함께 낡아 서로 어긋나지 않는다는 판단입니다.
요청마다 다시 재면 화면 하나에 파일 5개를 매번 읽게 됩니다.

이 절충이 맞는지, 아니면 파일 수정 시각(`st_mtime`)이 더 나은지.
그리고 **`?v=` 대신 경로에 해시를 넣는 방식**(`/static/js/calendar.fd0f2bcf.js`)이
Cloudflare 에서 더 안전한지 — 지금 방식은 쿼리를 캐시 키에 넣는다는
전제에 기대고 있습니다.

**② 전환을 "자리잡기 vs 조작" 으로 가른 것**

`body.booting` 이 첫 그림 동안 모든 `transition` 을 끄고, 두 번의
`requestAnimationFrame` 뒤에 풀립니다. 그래서 사이드바가 저장된 고정
상태로 **자리잡는 것**에는 전환이 안 붙고, 사람이 토글을 누른 것에는
붙습니다.

`requestAnimationFrame` 두 번이 미더운 신호인지, 더 정확한 지점이 있는지.

**③ `title` 의 기준을 자바스크립트로 정한 것**

첫 그림은 서버 매크로가, 그 뒤는 `retitle()` 이 만듭니다. 한 벌로 못 둔
이유는 옮긴 뒤 서버에 다시 묻지 않기 때문입니다(묻는 순간 보던 달을
잃습니다 — 4-13). 두 곳의 순서와 구분자를 맞추고 시험으로 묶었지만
**여전히 두 곳입니다.** 이 프로젝트에서 가장 자주 고쳐 온 모양이라
더 나은 길이 있는지 보고 싶습니다.

**④ `.out` 칸에서 점과 비침의 범위가 다른 것**

점은 이 달에만 놓고(`:not(.out)`), 비침은 격자에 보이는 칸까지 칠합니다.
그 칸만 비우면 띠가 중간에 끊겨 고장난 것처럼 읽혀서 이렇게 뒀습니다.
읽는 사람에게 이 차이가 혼란인지, 아니면 자연스러운지.

**⑤ 지난 라운드의 지적 ③ 이 옳았습니다**

"`:hover` 를 선언만 떠서 재는 것이 미더운지" 라고 물어보셨는데,
**미덥지 않았습니다.** 탐침에는 캐스케이드가 없어서 같은 버그가 다시
나도 초록입니다. CSS 규칙에 `.is-hover` 를 함께 걸고 실제 트리의 실제
요소에서 재도록 바꿨고, **옛 코드로 되돌려 빨개지는 것을 확인했습니다.**
