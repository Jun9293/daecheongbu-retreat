## 5. 특히 봐 주셨으면 하는 것

**① 작업 B — 패널이 정말 한 벌인가**

보드(`board.js`)와 달력(`calendar.js`)이 `drawer.js` 한 벌을 같이 씁니다.
화면이 넘기는 것은 `meta` · `onStatus` · `onDates` · `onAssignee` · `goTo` ·
`canGoTo` · `isTaskClick` · `afterLayout` 뿐입니다.
그 경계가 적절한지, 나중에 두 벌로 갈라질 여지가 남아 있는지 봐 주세요.

**② 작업 C 의 업로드 — 끊겼을 때 조각을 지우는 부분**

`attachments.py` 에서 조각으로 받다가 끊기면 반쯤 쓰인 파일을 지웁니다.
`except Exception` 이 아니라 `except BaseException` 인데(취소했을 때 오는
`ClientDisconnect` 가 `Exception` 계열이 아닐 수 있어서), 이게 맞는 판단인지.

**③ 백업 — 하드링크로 되돌리기가 성립하는가**

`backup.py` 의 `copy_uploads` 가 업로드 폴더가 안 바뀌었으면 다시 묶지 않고
지난 zip 에 하드링크를 겁니다. 되돌리는 절차("같은 날짜끼리 셋을 함께 되돌린다")가
그대로 성립하는지, 크기를 셀 때 하드링크를 한 번만 세는 것(`disk_used`)이 맞는지.

**④ C-4 가 미해결입니다 — 여기가 제일 궁금합니다**

Cloudflare 무료 터널로 **본문을 30초 넘게 보내면 끊깁니다.**
20MB 를 60초에 걸쳐 보냈더니 **12MB 째 36.6초에 끊겼습니다** — 크기가 아니라
시간입니다. 재 본 속도가 **2MB/s** 라 실제 한계는 **60MB 언저리**로 보이는데,
앱 상한은 **200MB** 입니다(로컬에서는 162MB 를 올리고 내려받아 sha256 까지 동일).

- 이 조합(앱 200MB / 터널 60MB)이 맞는 판단인지
- 다른 방법이 있는지
- 측정이 **로그인하지 않은 요청**이라 서버가 먼저 답한 탓일 가능성을 아직
  배제하지 못했습니다. 이걸 가르는 더 나은 확인 방법이 있는지
