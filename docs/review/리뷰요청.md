## 2. 무엇을 고쳤나

지난 리뷰에서 나온 것들입니다. 셋은 **지적이 맞았고**, 하나는 아니었습니다.

**① 접두사 없는 색을 없앴습니다.** `paint_of` 가 `background`/`border` 와
`dot_background`/`dot_border` 를 함께 주는데 앞엣것이 기본값처럼 보였습니다.
`bar_*` 로 바꿨습니다.

**② 보드 첫 렌더가 `paint_of` 를 안 지나고 있었습니다.** `make_row()` 가
`bar_style()` 을 직접 불러서, `paint_of` 는 API 경로만 쓰는 껍데기였고 첫
렌더가 세 번째 길로 남아 있었습니다. 이제 `bar_style` 을 부르는 곳은
`paint_of` 안의 두 번뿐입니다.

**③ `code_only` 가 문자열 안의 `//` 를 자르고 있었습니다.**
`"const u = 'https://x'; // 설명"` → `"const u = 'https:"`.
없음을 확인하는 시험이 그때 조용히 통과합니다 — 코드가 사라졌으니까요.

**④ 413 을 사람 말로 옮겼습니다.** Cloudflare 가 앞단에서 끊은 것이라
`detail` 이 없어 "올리지 못했습니다." 만 떴습니다. 문서의 근거도 시간에서
크기(100MB)로 고쳤습니다 — 시간으로 적어 두면 다음 사람이 상한을 60 으로
내립니다.

**⑤ 시험 날짜는 이미 상대 계산이었습니다.** 고칠 것이 없어서 아무것도
하지 않았고, 그 판단의 이유를 보고서 4장에 적었습니다.

## 5. 특히 봐 주셨으면 하는 것

**① `paint_of` 에 `ghost` 를 더한 것**

보드 첫 렌더를 지나게 하려면 고스트 바(관련팀 줄에 점선으로 뜨는 것)를
받아야 했습니다. 색은 무시되고 점선 테두리만 씁니다. 이게 `paint_of` 에
있을 일인지, 아니면 고스트는 애초에 다른 함수여야 하는지.

**② 부서 없는 업무의 색이 바뀝니다**

한 곳으로 모으면서 `#787774`(달력) 와 `#69726D`(보드) 중 뒤엣것으로
맞췄습니다. 부서가 **아예 없는** 업무의 달력 점만 해당하고 둘 다 회색입니다.
이런 조용한 변경을 이 정도로 넘겨도 되는지.

**③ `dot_of` 가 화면에 넘기는 키는 그대로 뒀습니다**

`background`/`border` 입니다. 접두사를 없애는 이유는 "무엇의 색인지 모르는
쌍" 을 없애려는 것인데, `dot_of` 는 이름 자체가 점이고 받는 쪽에도 점밖에
없어서 `dot.dot_background` 가 됩니다. 이 예외가 맞는지.

**④ `code_only` 를 어디까지 만들 것인가**

정규식 리터럴까지 따라갑니다(`/[&<>"]/g` 안의 따옴표를 문자열 시작으로
읽어 파일 절반이 사라진 적이 있어서). 자바스크립트를 제대로 해석하는 것이
아니라 "이 저장소에서 틀리지 않을 만큼" 인데, 이 선이 적당한지.

**⑤ 아직 남은 것 — 터널로 큰 파일 올리기**

앱 상한은 200MB, Cloudflare 는 요청 본문 100MB 입니다. 95MB 를 넘으면
**막지 않고 경고만** 합니다 — 집 안 회선에서는 올라가니까요.
**내려받기에는 이 제한이 없습니다.** 이 조합이 맞는 판단인지.
