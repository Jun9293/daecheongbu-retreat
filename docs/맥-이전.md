## 6. 맥미니의 전원·로그인 상태 (2026-09-30 · sudo 없이 읽기만)

`pmset -g` · `pmset -g custom` · `fdesetup status` · `defaults read /Library/Preferences/com.apple.loginwindow autoLoginUser` 로 읽은 값입니다. **바꾸지 않았습니다** — 바꾸는 것은 sudo 나 시스템 설정 화면이 필요합니다.

| 무엇 | 읽은 값 | 뜻 |
|---|---|---|
| 잠자기 | `sleep 0` (AC) | 시스템이 잠들지 않는다 — 윈도우 안내서 7-1 에 해당하는 것은 이미 됐다 |
| 디스플레이 잠자기 | `displaysleep 10` | 화면만 꺼진다. 서버와 무관 |
| 정전 후 자동 시동 | `autorestartatconnect 1` · `autorestart 0` | **켜져 있는 것으로 읽힌다** — 아래 3단계 재확인 |
| 네트워크로 깨우기 | `womp 1` | 켜져 있다 |
| FileVault | 꺼짐 | 자동 로그인이 가능한 조건 |
| 자동 로그인 | 사용자가 정해져 있음 · `kcpassword` 있음 | 재부팅하면 로그인까지 스스로 간다 → **LaunchAgent 가 뜬다** |

**그래서 5장 첫 줄(LaunchAgent 는 로그인해야 뜬다)은 지금 설정으로 풀려 있습니다** — 자동 로그인이 켜져 있기 때문입니다.

**3단계 재확인 (2026-09-30)** — 시스템 설정 화면에는 「전원이 연결되면 시작: 항상」 으로
보입니다. `pmset -g cap` 이 이 기계가 받는 설정으로 **`autorestart` 와 `autorestartatconnect`
를 따로** 내고, 화면의 그 항목과 이름·값이 맞는 것은 **`autorestartatconnect 1`** 입니다 —
**화면과 일치합니다.** `autorestart 0` 은 그와 별개인 옛 「정전 후 재시동」 키로 보입니다.
**2단계에서 「꺼져 있다」 고 적은 것은 뒤의 값만 본 판단이었습니다.** 다만 이것은 이름과
화면으로 맞춘 것이고 **전원을 실제로 뽑아 보지는 않았습니다** — 전환한 뒤 한가한 때에
한 번 뽑아 보고 스스로 서는지(8장 「전환 뒤」) 봅니다.

> **대가** — FileVault 가 꺼져 있고 자동 로그인이 켜져 있으면 기계를 손에 넣은 사람은 디스크와 로그인된 세션을 그대로 얻습니다. `data/` 에 DB · 서명키 · VAPID 키 · API 키가 있습니다. 이 둘을 그대로 둘지는 사람이 정합니다.

## 7. seed.py 를 돌리지 않는 까닭과 빈 맥에서 처음 켤 때

**`serve.sh` 는 seed 를 부르지 않습니다.** 윈도우의 `run.bat` 은 `data\app.db` 가 없으면
`seed.py` 를 불렀는데, 그 길로 2026-08-29 에 개발 시드가 그때 하나뿐인 DB 에 들어가 그대로
운영이 됐습니다(CLAUDE.md 0장 둘째 예외 · 6-9). 그 뒤로 `seed.py` 는 **운영 폴더(`data/`)를
가리키면 스스로 멈춥니다**(`운영경로인가`). 운영 자료는 시드로 만드는 것이 아니라 **윈도우에서
옮겨 오는 것**이라, 앱을 띄우는 스크립트가 시드를 알 이유가 없습니다.

**빈 맥에서 처음 켜면** — 운영 자료를 안 옮기고 `serve.sh`(또는 launchd)로 띄우면 앱이
**빈 DB** 에 표를 만들고 서명키를 새로 씁니다(2단계 검증에서 실제로 그렇게 떴습니다).
계정이 없으니 `scripts/계정문열기.py --첫관리자` 로 첫 관리자를 만듭니다 — **비밀번호가 창에
찍히므로 사람이 돌립니다**(11-2). 절차는 `docs/배포-안내.md` 15-4 입니다.
연습용 자료는 `DCB_DATA_DIR` 을 운영 폴더 밖으로 두고서만 시드를 씁니다.

### 8-2. 윈도우 — 내리고, 다시 안 켜지게 하고, 뜬다

**터널을 먼저 내립니다** — 바깥에서 쓰기가 들어오는 문을 먼저 닫아야 뜬 판 뒤에 쓰인 것이 없습니다.

```
sc.exe config Cloudflared start= demand
sc.exe stop Cloudflared
Disable-ScheduledTask -TaskName "대청부 앱"
Disable-ScheduledTask -TaskName "대청부 백업"
Get-NetTCPConnection -LocalPort 8000 -State Listen | Select-Object -ExpandProperty OwningProcess -Unique | ForEach-Object { Stop-Process -Id $_ -Force }
sc.exe query Cloudflared

```

**하나**인지 봅니다(이 명령은 Cloudflare 로그인 인증서가 있는 기계에서만 돕니다 — 8-6).

### 8-6. 자격증명 — 두 방식

| | ㄱ. 있는 터널의 자격증명을 복사 | ㄴ. 맥용 새 터널을 만든다 |
|---|---|---|
| 하는 일 | 윈도우 `.cloudflared\<터널 id>.json` 을 USB 로 맥 `~/.cloudflared/` 에 · `config.yml` 의 `tunnel`·`credentials-file` 은 그대로 | 맥에서 새 터널을 만들고 바깥 주소의 DNS 를 새 터널로 돌린다 |
| 좋은 점 | **Cloudflare 로그인 없이** 된다 · DNS 를 안 건드린다 · 롤백이 「윈도우 서비스 다시 켜기」 하나 | **두 기계가 같은 터널을 쥐지 않는다** — 주소는 DNS 가 가리키는 한 터널로만 간다. 비밀 파일을 기계 사이로 옮기지 않는다 · 윈도우 터널이 그대로 대기 |
| 나쁜 점 | **같은 터널을 두 기계가 쥔다** — 둘 다 켜지면 요청이 두 서버로 갈리고 두 DB 에 나눠 쓰인다(가장 비싼 사고). 비밀 파일이 USB 를 지난다 · 맥에서 `tunnel info` 를 쓰려면 따로 로그인 | Cloudflare 로그인이 **반드시** 필요 · DNS 를 바꾸는 것이 전환이라 몇 분 걸릴 수 있다 · 롤백도 DNS 를 되돌리는 일 · 다 끝나면 옛 터널을 정리할 일이 남는다 |
| **사람이 직접 할 것** | 윈도우에서 `.json` 을 찾아 USB 로 옮기기(메신저·메일 금지) · 바깥 확인 | `cloudflared tunnel login` 이 연 **브라우저에서 Cloudflare 로그인과 본인 확인(2단계 인증)** · 도메인 고르기 · DNS 를 바꾸는 명령 확인 · 바깥 확인 |
| 이 창이 할 수 있는 것 | `config.yml` 채우기 · plist 로드 · 로그 확인 | 로그인이 끝난 뒤의 `tunnel create` · `route dns --overwrite-dns` · plist 로드 |

ㄴ 의 명령(로그인이 끝난 뒤 · **새 터널 이름은 그날 정합니다**):

```bash
cloudflared tunnel login
cloudflared tunnel create <새 터널>
cloudflared tunnel route dns --overwrite-dns <새 터널> <바깥 주소>
```

**어느 쪽이든 두 기계가 함께 받지 않게 하는 안전장치는 같습니다** —
① 내리는 쪽은 **다시 켜지는 길**(윈도우 서비스 시작 유형 · 맥 LaunchAgents 의 plist)까지 끈다
② 올리기 전에 **내린 쪽이 정말 내려갔는지** 본다(`sc.exe query` · `launchctl print`)
③ 올린 뒤 **커넥터가 하나**인지 본다(ㄱ) · DNS 가 새 터널을 가리키는지 본다(ㄴ)
④ 이 차례는 **한 사람이 이 장을 위에서부터** 따라간다 — 두 사람이 두 기계를 나눠 맡지 않는다
