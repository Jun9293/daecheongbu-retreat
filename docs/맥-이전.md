# 맥미니 이전 — 2단계 (맥용 실행 파일)

**이 판은 작성과 로컬 검증까지입니다.** 터널 기동 · 실서비스 전환 · push ·
sudo 가 필요한 일은 안 했습니다. 운영의 정본은 아직 `docs/배포-안내.md`
(윈도우)이고, 전환하는 판에서 CLAUDE.md 11장 · 11-2 와 함께 고칩니다.

## 1. 윈도우 쪽에 있던 것 (읽기만 한 점검)

## 4. 로컬 검증 (2026-09-30 · 임시 데이터 폴더 · 포트 8765)

**운영 `data/` 는 쓰지 않았습니다** — 앱이 한 시간마다 도는 위험 점검이 알림을
쓰기 때문입니다. 시험용 plist 는 라벨을 `….test` 로 바꾼 사본이고 끝에 내렸습니다.

| 무엇 | 결과 |
|---|---|
| 직접 실행 → `/healthz` · `/login` | 200 · 200 · 127.0.0.1 에만 열림 |
| 두 번째 실행 | 포트를 쥔 PID 를 말하고 75 · 앞의 서버는 그대로 |
| 확인과 바인드 사이의 틈(시험용 스위치로 재현) | uvicorn 은 **3** 으로 끝났고 → 같은 말 · 75 |
| 포트와 무관한 실패(앱을 못 읽음) | 그대로 1 — 75 로 바꾸지 않는다 |
| 같은 설정 오류 세 번 | 첫 번째만 적고 둘째부터 0줄 · 다른 오류는 다시 적는다 · 한 번 뜨면 기억을 지운다 |
| 줄 끝 주석 · 환경 우선 | 줄 번호와 이름만 알림 · 따옴표 안 `#` 과 빈칸 없는 `#` 은 값으로 남음 |
| 가짜 비밀값을 넣고 출력 전체를 훑음 | 새지 않음(0건) |
| 로그 회전(뜰 때 · 도는 동안 · 두 세대 · 링크는 건너뜀) | 전부 기대대로 · 열린 채 쓰는 파일도 비운 뒤 앞에서 다시 씀 |
| launchd 로드 → 시작 | 2초 안에 200 |
| uvicorn `kill -9` · 셸 `kill -9` · SIGTERM | 약 30초 뒤 다시 섬 · 셸을 죽여도 uvicorn 이 남지 않음 |
| 포트가 막힌 채 로드 | 30초마다 75 로 물러섬 → 막던 것이 내려가자 launchd 가 이어받음 |
| bootout | 리스너 0 · 등록 해제 · 떠도는 uvicorn 0 |

## 5. 전환하기 전에 볼 것 (점검 제안)

- ~~LaunchAgent 는 로그인해야 뜬다~~ → **지금 설정으로 풀려 있다**(6장 · 자동 로그인). 정전 후 자동 시동만 남았다
- **백업과 알림 작업이 아직 맥에 없습니다** — 윈도우의 `대청부 백업`(03:00)·`대청부 알림`(08:00, 사용 안 함)에 해당하는 `StartCalendarInterval` plist 가 필요합니다. 백업이 없는 채로 전환하면 안 됩니다
- ~~로그는 뜰 때만 민다~~ → `로그밀기.sh` · 한 시간 LaunchAgent(로드는 전환하는 판에서)
- **KeepAlive 는 죽은 것만 살립니다** — 떠 있는데 답을 안 하는 서버는 못 알아챕니다(`/healthz` 를 보는 감시가 없습니다)
- ~~설정 오류(78)가 30초마다 쌓인다~~ → 같은 오류는 한 번만. **포트가 막힌 75 는 여전히 30초마다 한 줄씩 적습니다** — 남이 포트를 쥔 것은 사람이 알아야 할 일이라 그대로 두었습니다
- ~~`.env` 줄 끝 주석 · 셸에 남은 값~~ → 떼거나 이름만 알림
- **터널을 두 기계에서 동시에 돌리면 요청이 두 DB 로 갈립니다.** 윈도우를 먼저 내리고, 그 시점의 `data/`(DB · uploads · VAPID · 서명키)를 옮긴 뒤 맥을 올립니다
- **터널 plist 를 LaunchAgents 에 두면 다음 로그인에 저절로 붙습니다** — `plist-만들기.sh` 가 그 폴더를 거절하게 했습니다
- 윈도우 기준으로 적힌 자리는 CLAUDE.md 11-2 「맥미니」 절과 `docs/배포-안내.md` 15장으로 **나란히** 두었습니다. 전환하는 판에서 어느 쪽을 정본으로 할지 바꿉니다

## 6. 맥미니의 전원·로그인 상태 (2026-09-30 · sudo 없이 읽기만)

`pmset -g` · `pmset -g custom` · `fdesetup status` · `defaults read /Library/Preferences/com.apple.loginwindow autoLoginUser` 로 읽은 값입니다. **바꾸지 않았습니다** — 바꾸는 것은 sudo 나 시스템 설정 화면이 필요합니다.

| 무엇 | 읽은 값 | 뜻 |
|---|---|---|
| 잠자기 | `sleep 0` (AC) | 시스템이 잠들지 않는다 — 윈도우 안내서 7-1 에 해당하는 것은 이미 됐다 |
| 디스플레이 잠자기 | `displaysleep 10` | 화면만 꺼진다. 서버와 무관 |
| 정전 후 자동 시동 | `autorestart 0` | **꺼져 있다** — 정전 뒤 전기가 돌아와도 스스로 안 켜진다 |
| (함께 보인 값) | `autorestartatconnect 1` | 뜻을 확인하지 못했다 — 추정하지 않고 값만 적는다 |
| 네트워크로 깨우기 | `womp 1` | 켜져 있다 |
| FileVault | 꺼짐 | 자동 로그인이 가능한 조건 |
| 자동 로그인 | 사용자가 정해져 있음 · `kcpassword` 있음 | 재부팅하면 로그인까지 스스로 간다 → **LaunchAgent 가 뜬다** |

**그래서 5장 첫 줄(LaunchAgent 는 로그인해야 뜬다)은 지금 설정으로 풀려 있습니다** — 자동 로그인이 켜져 있기 때문입니다. 남은 것은 **정전 후 자동 시동** 하나이고, 켜는 것은 시스템 설정의 에너지 항목(또는 sudo 가 필요한 `pmset`)이라 사람이 합니다.

> **대가** — FileVault 가 꺼져 있고 자동 로그인이 켜져 있으면 기계를 손에 넣은 사람은 디스크와 로그인된 세션을 그대로 얻습니다. `data/` 에 DB · 서명키 · VAPID 키 · API 키가 있습니다. 이 둘을 그대로 둘지는 사람이 정합니다.

## 7. seed.py 를 돌리지 않는 까닭과 빈 맥에서 처음 켤 때

**`serve.sh` 는 seed 를 부르지 않습니다.** 윈도우의 `run.bat` 은 `data\app.db` 가 없으면
`seed.py` 를 불렀는데, 그 길로 2026-08-29 에 개발 시드가 그때 하나뿐인 DB 에 들어가 그대로
운영이 됐습니다(CLAUDE.md 0장 둘째 예외 · 6-9). 그 뒤로 `seed.py` 는 **운영 폴더(`data/`)를
가리키면 스스로 멈춥니다**(`운영경로인가`). 운영 자료는 시드로 만드는 것이 아니라 **윈도우에서
옮겨 오는 것**이라, 앱을 띄우는 스크립트가 시드를 알 이유가 없습니다.

**빈 맥에서 처음 켜면** — 운영 자료를 안 옮기고 `serve.sh`(또는 launchd)로 띄우면 앱이
**빈 DB** 에 표를 만들고 서명키를 새로 씁니다(2단계 검증에서 실제로 그렇게 떴습니다).
계정이 없으니 `scripts/계정문열기.py --첫관리자` 로 첫 관리자를 만듭니다 — **비밀번호가 창에
찍히므로 사람이 돌립니다**(11-2). 절차는 `docs/배포-안내.md` 15-4 입니다.
연습용 자료는 `DCB_DATA_DIR` 을 운영 폴더 밖으로 두고서만 시드를 씁니다.
