# 배포 안내

집에 있는 윈도우 컴퓨터를 서버로 씁니다. 공유기 설정을 건드리지 않고,
Cloudflare 라는 회사가 대신 길을 열어 줍니다(무료).

**명령어를 몰라도 됩니다.** 검은 창에 적힌 대로 붙여넣기만 하면 됩니다.
각 단계 끝에 **"이렇게 나오면 성공"** 을 적어 두었으니 그것과 같으면 다음으로 넘어가세요.

전부 합쳐 **한 시간쯤** 걸립니다. 중간에 끊고 다음에 이어서 해도 됩니다.

---

## 준비물

| | |
|---|---|
| 항상 켜 둘 윈도우 컴퓨터 | 노트북이어도 됩니다. **절전이 켜져 있으면 밤에 접속이 끊깁니다** — 7번에서 끕니다 |
| 도메인 하나 | `recba12.com` — **Cloudflare 에서 직접 사면 가장 간단합니다.** 그러면 2번을 건너뜁니다 |
| Cloudflare 계정 | 무료. cloudflare.com 에서 가입 |

> **도메인이 꼭 필요한가요?**
> 없어도 임시 주소로 쓸 수는 있는데, 컴퓨터를 껐다 켤 때마다 주소가 바뀝니다.
> 19명에게 매번 새 주소를 알려야 하므로 도메인을 사는 편이 훨씬 편합니다.
>
> **Cloudflare 에서 직접 사면** 네임서버가 이미 Cloudflare 것이라 2번이 필요 없습니다.
> `recba12.com` 은 그렇게 산 것이므로 **3번부터 시작하시면 됩니다.**

---

## 1. 검은 창(명령 프롬프트) 여는 법

앞으로 계속 씁니다.

1. 키보드에서 **윈도우 키**를 누릅니다
2. `cmd` 라고 칩니다
3. **명령 프롬프트**가 나오면 엔터

검은 창이 뜨면 아래를 붙여넣고 엔터를 칩니다. (붙여넣기는 마우스 오른쪽 클릭)

```
cd /d "C:\Users\user\Desktop\대청부-수련회-시스템"
```

**이렇게 나오면 성공** — 창 왼쪽에 `C:\Users\user\Desktop\대청부-수련회-시스템>` 이 보입니다.

---

## 2. 도메인을 Cloudflare 에 연결하기

> **Cloudflare 에서 직접 산 경우 이 단계는 건너뜁니다.**
> `recba12.com` 이 그렇습니다 — 이미 Cloudflare 가 관리하고 있으므로 **3번으로 넘어가세요.**
>
> 아래는 가비아·후이즈 같은 **다른 곳에서 산 경우**에만 하는 절차입니다.

산 도메인의 "관리를 Cloudflare 에 맡긴다"는 절차입니다. 한 번만 하면 됩니다.

1. `cloudflare.com` 에 로그인
2. 가운데 **Add a site**(사이트 추가) 를 누릅니다
3. 산 도메인을 칩니다 (`recba12.com` 처럼 `www` 없이)
4. 요금제가 나오면 **Free** 를 고릅니다
5. 잠시 뒤 화면에 **네임서버 두 개**가 나옵니다. 이렇게 생겼습니다:
   ```
   ana.ns.cloudflare.com
   rick.ns.cloudflare.com
   ```
   이 두 줄을 복사해 둡니다
6. **도메인을 산 곳**(가비아 등)에 로그인 → 그 도메인의 **네임서버 설정** 메뉴로 갑니다
7. 원래 적혀 있던 것을 지우고 위의 두 개를 넣고 저장합니다

**이렇게 나오면 성공** — Cloudflare 화면의 도메인 옆이 **Active**(활성) 로 바뀝니다.
바뀌는 데 **10분~몇 시간** 걸립니다. 기다리는 동안 3번을 먼저 해도 됩니다.

## 3. cloudflared 설치하기

바깥에서 우리 컴퓨터로 오는 길을 여는 프로그램입니다.

1. 브라우저에서 아래를 엽니다
   ```
   https://github.com/cloudflare/cloudflared/releases/latest
   ```
2. 목록에서 **`cloudflared-windows-amd64.exe`** 를 내려받습니다
3. 내려받은 파일의 **이름을 `cloudflared.exe` 로 바꿉니다**
4. `C:\cloudflared\` 라는 폴더를 만들고 그 안에 넣습니다

검은 창에서 확인:

```
C:\cloudflared\cloudflared.exe --version
```

**이렇게 나오면 성공** — `cloudflared version 2026.x.x` 처럼 버전이 찍힙니다.

---

## 4. Cloudflare 에 로그인

```
C:\cloudflared\cloudflared.exe tunnel login
```

**브라우저가 저절로 열립니다.** 거기서:

1. Cloudflare 계정으로 로그인
2. 도메인 목록이 나오면 **아까 등록한 도메인을 클릭**
3. 파란 **Authorize**(승인) 버튼을 누릅니다

**이렇게 나오면 성공** — 검은 창에
`You have successfully logged in.` 과 `cert.pem` 파일 경로가 찍힙니다.
브라우저는 닫아도 됩니다.

---

## 5. 터널 만들기

세 줄입니다. 한 줄씩 붙여넣고 엔터.

```
C:\cloudflared\cloudflared.exe tunnel create daecheongbu
```

**이렇게 나오면 성공** — `Created tunnel daecheongbu with id 8f2a...` 처럼
**긴 id** 가 찍힙니다. **이 id 를 메모장에 복사해 두세요.** 다음 단계에서 씁니다.

이어서 — 아래는 실제 주소가 그대로 들어가 있으니 그냥 붙여넣으면 됩니다:

```
C:\cloudflared\cloudflared.exe tunnel route dns daecheongbu retreat.recba12.com
```

**이렇게 나오면 성공** — `Added CNAME retreat.recba12.com` 이 찍힙니다.
앞으로 이 주소로 접속합니다.

---

## 6. 터널 설정 파일 만들기

1. 윈도우 키 → `메모장` → 엽니다
2. 아래를 붙여넣고 **`8f2a...` 자리 두 곳에 5번에서 메모한 id** 만 넣습니다 (주소는 그대로 두세요)

```yaml
tunnel: 8f2a여기에-메모한-id
credentials-file: C:\Users\user\.cloudflared\8f2a여기에-메모한-id.json

ingress:
  - hostname: retreat.recba12.com
    service: http://127.0.0.1:8000
  - service: http_status:404
```

3. **파일 → 다른 이름으로 저장**
   - 위치: `C:\Users\user\.cloudflared\`
   - 파일 이름: `config.yml` (따옴표 포함해서 **`"config.yml"`** 로 적으세요 —
     그래야 `config.yml.txt` 가 되지 않습니다)
   - 인코딩: **UTF-8**

**이렇게 나오면 성공** — 그 폴더에 `config.yml` 이 보이고, 파일 종류가 `YML 파일` 입니다.

## 7. 컴퓨터가 잠들지 않게 하기

**여기서 가장 많이 막힙니다.** 윈도우는 기본으로 30분쯤 지나면 절전에 들어갑니다.
절전되면 앱도 터널도 멈춰서 밤이나 주말에 아무도 접속하지 못합니다.
**오류가 뜨지 않고 그냥 안 열립니다** — 뭐가 잘못됐는지 알기 어려운 종류입니다.

### 7-1. 절전 끄기

1. 윈도우 키 → `전원 및 절전` → 엽니다
2. **화면 끄기는 그대로 둬도 됩니다** (화면만 꺼지는 것이라 서버는 계속 돕니다)
3. **절전** 을 전부 **"안 함"** 으로 바꿉니다

노트북이면 칸이 두 벌 나옵니다. **둘 다** 바꾸세요.

| | |
|---|---|
| 전원 연결 시 | 절전 → **안 함** |
| 배터리 사용 시 | 절전 → **안 함** |

### 7-2. 덮개를 닫아도 안 꺼지게

노트북일 때만 해당합니다.

1. 윈도우 키 → `제어판` → 엽니다
2. **하드웨어 및 소리** → **전원 옵션**
3. 왼쪽에서 **덮개를 닫을 때 수행할 작업**
4. **배터리 사용** 과 **전원 사용** 둘 다 **아무 것도 안 함** 으로

### 7-3. 빠른 시작 끄기

빠른 시작이 켜져 있으면 컴퓨터를 껐다 켤 때 완전히 새로 켜지는 것이 아니라
**자다 깨는 것에 가깝습니다.** 그래서 "시작할 때" 트리거(8-2)가 안 도는 경우가 있습니다.

1. 같은 **전원 옵션** 화면에서 왼쪽의 **전원 단추 작동 설정**
2. 위쪽 **현재 사용할 수 없는 설정 변경** 을 먼저 누릅니다 (이걸 눌러야 아래가 켜집니다)
3. **종료 설정** 의 **빠른 시작 켜기** 체크를 **해제**
4. **변경 내용 저장**

**이렇게 나오면 성공** — 자리를 **30분 넘게** 비웠다가(화면이 꺼진 뒤에도)
휴대폰으로 `https://retreat.recba12.com` 을 열었을 때 로그인 화면이 뜹니다.
컴퓨터를 만지지 않은 채로 열려야 제대로 된 것입니다.

## 8. 앱을 서비스처럼 돌리기

### 8-1. 첫 관리자 계정 만들기

검은 창에서 — **`<이름>` 과 `<연락처>` 를 본인 것으로 바꿔서** 치세요.

```
.venv\Scripts\python.exe scripts/create_admin.py "<이름>" <연락처>
```

> **아래의 예시를 그대로 복사해 넣지 마세요.** 실제로 그런 일이 있었습니다 —
> 안내서에 적혀 있던 예시 번호가 그대로 들어가 **관리자 계정이 하나 더 생겼습니다.**
> 그래서 이 문서에서 예시 번호를 아예 뺐습니다.

**이렇게 나오면 성공** — 아래처럼 **초대 링크**가 한 번 찍힙니다.

```
'<이름>' 관리자 계정을 만들었습니다.

아래 주소를 그대로 복사해서 카카오톡으로 보내시면 됩니다.
이 링크는 지금 한 번만 보입니다 — 원문을 저장하지 않기 때문입니다.
  https://retreat.recba12.com/invite/kZ3n...
```

**주소가 완성된 채로 나옵니다.** 손댈 곳이 없으니 그대로 복사하세요 —
예전에는 주소 앞부분을 자리표시자로 두고 손으로 갈아 끼우게 했는데,
그러다 뒤의 토큰까지
건드려 링크가 자주 깨졌습니다.

주소가 `retreat.recba12.com` 이 아니면 **환경변수로 한 번만** 알려주면 됩니다:

```
setx DCB_BASE_URL https://내주소.example.com
```

작업 스케줄러로 띄우는 앱과 스크립트가 같은 값을 씁니다.

**링크를 잃어버렸으면 계정을 다시 만들지 마세요.** 초대 링크는 한 번 쓰면
만료되므로 다시 받을 일이 자주 생깁니다. 그때는 **링크만** 다시 받습니다:

```
.venv\Scripts\python.exe scripts/create_admin.py --reissue <연락처>
```

> **계정을 다시 만들면 같은 사람이 둘이 됩니다.** 그러면 알림이 두 번 가고
> (총무팀 알림은 관리자 전원에게 갑니다) 담당자를 고를 때 같은 이름이 여럿 뜹니다.
> 이미 그렇게 된 계정은 `scripts/merge_users.py` 로 확인하고 정리합니다 —
> 지우지 않고 **비활성화만** 하므로 지난 기록은 그대로 남습니다.
>
> 지금 중복이 있는지는 자가진단(9번)이 알려줍니다.

### 8-2. 앱을 자동으로 켜지게 하기

컴퓨터를 껐다 켜도 알아서 돌게 합니다.

1. 윈도우 키 → `작업 스케줄러` → 엽니다
2. 오른쪽에서 **작업 만들기**(Create Task) — *기본 작업*이 아니라 **작업 만들기**입니다
3. **일반** 탭
   - 이름: `대청부 앱`
   - **사용자가 로그온했는지 여부에 관계없이 실행** 을 고릅니다
   - **가장 높은 수준의 권한으로 실행** 에 체크
4. **트리거** 탭 → 새로 만들기 → 작업 시작: **시작할 때** → 확인
5. **동작** 탭 → 새로 만들기 → 프로그램/스크립트에 아래를 넣습니다
   ```
   C:\Users\user\Desktop\대청부-수련회-시스템\scripts\serve.bat
   ```
6. **설정** 탭 → *작업이 실패하면 다시 시작 간격* 에 체크, `1분` / `3번`
7. 확인 → 윈도우 로그인 비밀번호를 물으면 넣습니다

같은 방법으로 두 개를 더 만듭니다.

| 이름 | 트리거 | 프로그램/스크립트 | 인수 |
|---|---|---|---|
| `대청부 백업` | 매일 새벽 3:00 | `C:\Users\user\Desktop\대청부-수련회-시스템\.venv\Scripts\python.exe` | `scripts/backup.py` |
| `대청부 알림` | 매일 아침 8:00 | `C:\Users\user\Desktop\대청부-수련회-시스템\.venv\Scripts\python.exe` | `scripts/notify.py` |

두 작업 모두 **시작 위치**에 `C:\Users\user\Desktop\대청부-수련회-시스템` 을 넣어주세요.

> **6번의 "실패하면 다시 시작" 은 `대청부 앱` 에만 넣습니다.**
> 백업과 알림에는 넣지 마세요 — 백업에 붙으면 새벽에 백업 파일이 3개 생기고,
> 알림에 붙으면 같은 알림이 여러 번 갑니다. 앱은 계속 떠 있어야 하는 것이라
> 다시 시작이 맞지만, 저 둘은 하루 한 번 돌고 끝나는 일입니다.

> **알림 작업은 만들어만 두고 "사용 안 함" 으로 두세요.**
> 목록에서 오른쪽 클릭 → **사용 안 함**.
> 몇 주 동안 `/admin/notify/preview` 화면으로 "오늘 누구에게 무엇이 갈지" 를
> 지켜본 뒤에 켜는 것이 안전합니다. 틀린 알림을 세 번 받은 사람은
> 그 뒤로 알림을 보지 않습니다.

### 8-3. cloudflared 를 서비스로 등록

**`service install` 만 해서는 안 됩니다.** 실제로 겪은 것을 그대로 적어 둡니다.
서비스 목록에 `Cloudflare Tunnel` 은 생기는데, 시작하면 **종료 코드 1067** 로
곧바로 멈추고 상태가 `STOPPED` 로 돌아갑니다.

이유는 둘입니다.

1. 서비스는 **LocalSystem** 계정으로 도는데, 6번에서 만든 `config.yml` 은
   `C:\Users\user\.cloudflared\` 즉 **내 사용자 폴더**에 있습니다.
   LocalSystem 에게 그 폴더는 자기 폴더가 아니라서 설정을 찾지 못합니다
2. `service install` 이 등록하는 실행 경로에 **`--config` 옵션이 아예 붙지 않습니다.**
   그래서 "설정이 어디 있는지" 를 알려줄 방법이 없습니다

**검은 창을 관리자 권한으로 열고** 순서대로 합니다.
(윈도우 키 → `cmd` → 오른쪽 클릭 → **관리자 권한으로 실행**)

1. 서비스를 등록합니다

   ```
   C:\cloudflared\cloudflared.exe service install
   ```

2. LocalSystem 이 보는 설정 폴더를 만듭니다

   ```
   mkdir "C:\Windows\System32\config\systemprofile\.cloudflared"
   ```

3. 6번에서 만든 `config.yml` 을 그 폴더로 복사합니다

   ```
   copy "C:\Users\user\.cloudflared\config.yml" "C:\Windows\System32\config\systemprofile\.cloudflared\config.yml"
   ```

   `.json` 인증 파일은 옮기지 않아도 됩니다 — `config.yml` 안의
   `credentials-file:` 이 원래 자리를 절대 경로로 가리키고 있기 때문입니다.

4. 실행 경로에 `--config` 를 직접 붙입니다.
   **`binPath=` 뒤의 빈 칸 한 칸은 반드시 있어야 합니다** — `sc` 명령의 문법입니다

   ```
   sc config Cloudflared binPath= "C:\cloudflared\cloudflared.exe --config C:\Windows\System32\config\systemprofile\.cloudflared\config.yml tunnel run"
   ```

5. **껐다 켭니다.** 설정을 바꿔도 이미 돌고 있는 서비스에는 반영되지 않습니다

   ```
   net stop Cloudflared
   net start Cloudflared
   ```

**이렇게 나오면 성공**

```

## 12. 고친 것을 반영하려면 — 다시 켜기

파이썬은 **켤 때 읽은 코드를 그대로 들고 있습니다.** 그래서 코드를 고쳤으면
서버를 껐다 켜야 반영됩니다. 그런데 껐다고 생각했는데 안 꺼지는 경우가 있어서,
그 절차를 여기 적어 둡니다.

> **왜 이 장이 생겼나** — 작업 스케줄러에서 작업을 멈추면 **작업만 멈추고
> 그 아래 파이썬은 그대로 남습니다.** 포트 8000 은 계속 열려 있으니 겉으로는
> 재시작된 것처럼 보이는데, 실제로는 **어제 뜬 프로세스가 그대로 답합니다.**
> 화면(HTML)만 새것으로 바뀌고 코드는 옛것이라 짝이 안 맞아,
> 상세 패널이 `Drawer is not defined` 로 열리지 않았습니다.
>
> 프로세스가 셋으로 이어져 있어서 그렇습니다:
> **`cmd.exe`(serve.bat) → `python.exe` → `python.exe`(8000 을 쥔 쪽)**.
> 작업을 멈추면 맨 위만 없어집니다.

### 12-1. 그대로 붙여넣기

**파워셸을 "관리자 권한으로 실행" 해서** 여세요 (윈도우 키 → `powershell` 을
치고 → 오른쪽 클릭 → **관리자 권한으로 실행**). 작업이 관리자 권한으로 돌기
때문에, 일반 창에서는 멈추지도 끝내지도 못합니다.

아래를 통째로 복사해 붙여넣으세요.

```
$포트 = 8000
$작업 = "대청부 앱"
function 쥔PID { Get-NetTCPConnection -LocalPort $포트 -State Listen -ErrorAction SilentlyContinue |
                 Select-Object -ExpandProperty OwningProcess -Unique }

$전 = 쥔PID
"멈추기 전 PID: $($전 -join ', ')"

Stop-ScheduledTask -TaskName $작업 -ErrorAction SilentlyContinue
foreach ($id in $전) { Stop-Process -Id $id -Force -ErrorAction SilentlyContinue }

$끝 = (Get-Date).AddSeconds(10)
while ((쥔PID) -and (Get-Date) -lt $끝) { Start-Sleep -Milliseconds 500 }
$남음 = 쥔PID

if ($남음) {
  "!! 아직 $($남음 -join ', ') 이(가) $포트 를 쥐고 있습니다. 관리자 창인지 확인하세요."
} else {
  "포트가 비었습니다"
  Start-ScheduledTask -TaskName $작업
  $끝 = (Get-Date).AddSeconds(30)
  do { Start-Sleep -Milliseconds 500; $후 = 쥔PID } while (-not $후 -and (Get-Date) -lt $끝)
  "다시 켠 뒤 PID: $($후 -join ', ')"

  # **집합으로 견줍니다.** `$후 -ne $전` 은 둘 다 배열일 때 비교가 아니라
  # 필터로 돌아서, 옛 프로세스가 그대로 남아 있어도 "성공" 이라고 말합니다.
  # 하나라도 겹치면 아직 안 꺼진 것입니다.
  $겹침 = @($후 | Where-Object { $전 -contains $_ })
  if (-not $후) { "실패 — 다시 뜨지 않았습니다. data\server.log 를 보세요" }
  elseif ($겹침.Count -gt 0) {
    "실패 — $($겹침 -join ', ') 이(가) 그대로입니다. 아직 옛 코드가 돌고 있습니다"
  } else { "성공 — PID 가 바뀌었습니다" }
}
```

**이렇게 나오면 성공** — 마지막 줄이 이렇습니다.

```
멈추기 전 PID: 30456
포트가 비었습니다
다시 켠 뒤 PID: 31872
성공 — PID 가 바뀌었습니다
```

**PID(프로세스 번호)가 바뀌는 것으로 확인합니다.** 포트가 열려 있는 것으로는
알 수 없습니다 — 안 꺼진 옛 프로세스도 포트를 쥐고 똑같이 답하기 때문입니다.
그것이 이 장이 생긴 이유입니다.

> **번호를 `-ne` 로 견주지 마세요.** 포트를 쥔 것이 둘 이상이면 양쪽이 배열이
> 되는데, 파워셸에서 배열끼리의 `-ne` 는 비교가 아니라 **필터**입니다.
> 결과가 비지 않으므로 `if` 가 참이 되고, **옛 프로세스가 그대로 남아 있어도
> "성공" 이 뜹니다.** 겹치는 번호가 하나라도 있는지로 봐야 합니다.
> 위 스크립트가 그렇게 되어 있습니다.

### 12-2. 손으로 하려면

붙여넣기가 내키지 않으면 이 순서입니다. **순서를 지켜야 합니다.**

1. 파워셸을 **관리자 권한으로** 엽니다
2. 지금 번호를 적어 둡니다
   ```
   Get-NetTCPConnection -LocalPort 8000 -State Listen | Select-Object OwningProcess
   ```
3. 작업 스케줄러에서 `대청부 앱` 오른쪽 클릭 → **끝내기**(End)
   — *중지*가 아니라 **끝내기**입니다
4. **그래도 남아 있는 것을 끝냅니다.** 2번에서 본 번호로:
   ```
   Stop-Process -Id 30456 -Force
   ```
5. 2번을 다시 해서 **아무것도 안 나오는지** 봅니다. 나오면 4번을 다시 합니다
6. 작업 스케줄러에서 `대청부 앱` 오른쪽 클릭 → **실행**
7. 2번을 다시 해서 **번호가 바뀌었는지** 봅니다

> **3번과 4번을 붙여서 하세요.** `대청부 앱` 에는 *작업이 실패하면 1분마다
> 3번까지 다시 시작* 이 걸려 있습니다(8-2). 작업을 멈추지 않고 파이썬만
> 끝내면 1분 뒤에 저절로 되살아나서, 껐는지 켰는지 알 수 없게 됩니다.

> **PID 를 못 보겠으면** 이렇게 하면 이름까지 나옵니다:
> ```
> Get-NetTCPConnection -LocalPort 8000 -State Listen |
>   ForEach-Object { Get-Process -Id $_.OwningProcess } |
>   Select-Object Id, ProcessName
> ```

### 12-2-1. `실패 — 다시 뜨지 않았습니다` 가 나오면 **먼저 충전기를 꽂으세요**

12-1 을 돌렸는데 이렇게 나오는 일이 있습니다.

```
멈추기 전 PID:
포트가 비었습니다
다시 켠 뒤 PID:
실패 — 다시 뜨지 않았습니다. data\server.log 를 보세요
```

`server.log` 를 봐도 **아무 오류가 없습니다.** 앱이 잘못된 것이 아니라
**작업 스케줄러가 아예 안 띄운 것**이기 때문입니다.

`대청부 앱` 에는 **"컴퓨터의 AC 전원이 켜져 있는 경우에만 작업 시작"**
(`DisallowStartIfOnBatteries`)이 걸려 있습니다. 노트북이 **배터리로 돌고
있으면** 작업이 `대기 중`(Queued)에 머물고 **영영 시작되지 않습니다.**

- 확인 — `(Get-ScheduledTask -TaskName '대청부 앱').State` 가 `Queued` 이고
  `Get-CimInstance Win32_Battery` 의 `BatteryStatus` 가 `1`(방전 중)이면 이것입니다
- **고치는 법은 충전기를 꽂는 것입니다.** 꽂고 12-1 을 다시 돌리면 뜹니다
- 급하면 **손으로 띄웁니다** — 이러면 전원과 상관없이 뜹니다.
  다만 스케줄러가 관리하지 않으므로, 나중에 충전기를 꽂고 12-1 로
  다시 정리하세요

  ```
  Start-Process -FilePath "C:\Users\user\Desktop\대청부-수련회-시스템\scripts\serve.bat" `
      -WorkingDirectory "C:\Users\user\Desktop\대청부-수련회-시스템" -WindowStyle Hidden
  ```

> **이 설정을 끄지 마세요.** 배터리로 돌 때 앱이 안 뜨는 것은 불편하지만,
> 집 서버는 콘센트에 꽂혀 있는 것이 정상입니다. **꽂혀 있지 않다는 것을
> 알려 주는 신호**이기도 합니다 — 그 상태로 며칠 두면 어느 날 배터리가
> 떨어져 서버가 통째로 사라집니다.

## 13. 평소에 알아둘 것

**백업은 자동입니다.** 매일 새벽 3시에 `data\backups\` 에 쌓이고 30개까지 남습니다.

**세 가지는 잃으면 안 됩니다.**

| 대상 | 잃으면 | 백업 파일 이름 |
|---|---|---|
| `data\app.db` | 모든 기록이 사라집니다 | `app-날짜.db` |
| `data\vapid_private.pem` | 알림 구독이 **전부 조용히 죽습니다** (오류도 안 납니다) | `vapid-날짜.pem` |
| `data\uploads\` 폴더 | 올린 **파일이 전부 사라집니다** (첨부파일 · 영수증) | `uploads-날짜.zip` |

> **업로드 폴더가 새로 들어왔습니다.** 첨부파일은 DB 안이 아니라 이 폴더에 쌓입니다.
> `app.db` 만 되돌리면 **목록에는 파일이 있는데 눌러도 열리지 않습니다** —
> 되돌리고 나서야 알게 되는 종류의 실패입니다. 그래서 폴더째 zip 으로 함께 남깁니다.
> (올라온 파일이 하나도 없으면 zip 을 만들지 않습니다. 정상입니다)

집 컴퓨터가 고장 나면 백업도 같이 사라지므로 **가끔 밖으로 복사해두세요.**
다만 **폴더째 통째로 복사하면 안 됩니다.**

> **왜 통째로 복사하면 안 되나** — 업로드 zip 은 내용이 안 바뀌면 다시 묶지
> 않고 지난 것과 **한 파일을 같이 가리키게** 해 둡니다(하드링크). 그래서 이
> 컴퓨터에서는 30벌이 있어도 실제로는 몇 벌 크기밖에 안 씁니다.
>
> 그런데 **USB(exFAT)·구글 드라이브·원드라이브는 그 이어짐을 모릅니다.**
> 복사하는 순간 전부 진짜 파일로 펼쳐집니다 — 업로드가 1GB 면 30벌이
> **30GB** 가 됩니다. 복사가 끝나지 않거나 용량이 꽉 찹니다.

**최근 몇 벌만 복사하세요.** 파워셸에 그대로 붙여넣으면 됩니다
(최근 3벌 = DB·업로드·키 각각 3개):

```
$원본 = "C:\Users\<사용자>\Desktop\대청부-수련회-시스템\data\backups"
$받을곳 = "D:\대청부백업"          # USB 나 클라우드 폴더로 바꾸세요
New-Item -ItemType Directory -Force $받을곳 | Out-Null
Get-ChildItem $원본 -Filter "app-*.db" |
  Sort-Object Name -Descending | Select-Object -First 3 | ForEach-Object {
    $날짜 = $_.BaseName -replace '^app-',''
    Get-ChildItem $원본 -Filter "*-$날짜.*" | Copy-Item -Destination $받을곳 -Force
  }
```

**이렇게 나오면 성공** — `$받을곳` 에 `app-…db` · `uploads-…zip` · `vapid-…pem` 이
날짜별로 세 벌씩 들어 있습니다.

> **옛 zip 을 열어서 고쳐 저장하지 마세요.** 같은 파일을 가리키던 다른 날짜의
> zip 도 **함께 바뀝니다.** 안을 들여다보는 것은 괜찮습니다 — 고쳐 저장하는
> 것만 하지 마세요. 되돌릴 때는 원본을 그대로 두고 **풀어서** 씁니다.

**되돌리려면** — 서버를 끄고, 같은 날짜끼리 셋을 함께 되돌립니다.

1. `data\backups\app-날짜.db` 를 `data\app.db` 로 덮어씁니다
2. `data\backups\vapid-날짜.pem` 을 `data\vapid_private.pem` 으로 덮어씁니다
3. `data\backups\uploads-날짜.zip` 을 풀어 `data\uploads\` 에 덮어씁니다
4. 서버를 다시 켭니다

**셋을 같은 날짜로 맞추세요.** DB 는 어제 것, 파일은 오늘 것으로 섞으면 목록과
실제 파일이 어긋납니다.

**주소를 바꾸고 싶으면** 5번의 `tunnel route dns` 를 새 주소로 다시 실행하고
`config.yml` 의 `hostname` 도 바꾸면 됩니다.

## 14. 회의록을 읽게 하기 — Claude API 키 넣기

회의록을 저장하면 시스템이 그 내용을 읽고 **결정사항 · 논의 · 새 업무**를
제안합니다. 그러려면 Claude API 키가 필요합니다.

**키가 없어도 앱은 멀쩡히 돕니다.** 제안이 안 나오는 것이 아니라, 회의록과
업무 **이름이 겹치는 정도로만** 골라 줍니다. 화면 위쪽에 그렇게 적힙니다 —
`회의록과 이름이 겹치는 업무입니다. 내용을 읽지는 않았습니다.`

### 14-1. 키 받기

1. 브라우저에서 <https://console.anthropic.com> 을 엽니다
2. 로그인합니다 (계정이 없으면 만듭니다)
3. 왼쪽 메뉴에서 **API Keys** 를 누릅니다
4. **Create Key** 를 누릅니다
5. 이름을 아무거나 적습니다 (예: `대청부 회의록`) → **Create Key**
6. `sk-ant-` 로 시작하는 긴 글자가 뜹니다. **이 화면을 닫으면 다시 못 봅니다.**
   그 자리에서 복사하세요

> **결제 수단을 등록해야 씁니다.** 콘솔의 **Plans & Billing** 에서 넣습니다.
> 회의 하나를 읽는 데 드는 값은 14-5 에 적어 두었습니다.

### 14-2. 키를 파일로 넣기 (이 방법을 쓰세요)

1. 파일 탐색기를 엽니다
2. 주소창에 아래를 붙여넣고 엔터

   ```
   C:\Users\user\Desktop\대청부-수련회-시스템\data
   ```

3. 그 폴더 **빈 곳에 오른쪽 클릭** → **새로 만들기** → **텍스트 문서**
4. 이름을 **`anthropic_key.txt`** 로 바꿉니다

   > 이름 뒤에 `.txt` 가 두 번 붙지 않게 하세요 (`anthropic_key.txt.txt`).
   > 확장자가 안 보이면 탐색기 위쪽 **보기 → 파일 확장명** 을 켜고 확인합니다.

5. 그 파일을 **메모장으로 열고**, 14-1 에서 복사한 키를 **붙여넣습니다**
6. **저장**하고 닫습니다

   > 키 **하나만** 넣으세요. 따옴표·`=`·설명을 함께 적지 마세요.
   > 앞뒤 공백과 줄바꿈은 앱이 알아서 떼어 냅니다.

7. 서버를 **다시 켭니다** (12-1). 켤 때 한 번만 읽습니다

**이 파일은 저장소에 올라가지 않습니다.** `.gitignore` 에 걸어 두었습니다 —
저장소가 공개라(11-2) 키가 한 번 올라가면 **지우고 커밋해도 히스토리에
남습니다.**

### 14-3. 됐는지 확인하기

회의록 하나를 열고 **저장**을 누릅니다. 아래 `이 회의록에서 제안` 칸의
첫 줄을 보세요.

| 보이는 것 | 뜻 |
|---|---|
| `회의 내용을 읽고 골랐습니다.` | 됐습니다 |
| `회의 내용을 읽는 중입니다…` | 도는 중입니다. 몇 초 뒤 저절로 바뀝니다 |
| `아직 연결되지 않았습니다` | 키를 못 찾았습니다 — 14-2 를 다시 보세요 |
| `응답이 401 입니다` | 키가 틀렸습니다. 콘솔에서 새로 만들어 넣으세요 |
| `응답이 400 입니다 (…credit…)` | 결제 수단이나 잔액을 확인하세요 |

### 14-4. 키가 만료되면

**Anthropic 콘솔에서 만든 키에는 만료일이 없습니다.** 지우거나(Revoke)
계정 결제가 막히기 전까지 그대로 씁니다.

**그래서 조용히 고장 나는 길은 둘입니다.**

- 콘솔에서 키를 **지웠을 때** — `응답이 401 입니다` 가 뜹니다
- **잔액이 떨어졌을 때** — `응답이 400 입니다` 가 뜹니다

둘 다 화면에 그대로 적힙니다. **제안이 안 나오는 것이 아니라 낱말이 겹치는
정도로 물러섭니다** — 아무 말 없이 비는 일은 없습니다.

> 키를 새로 만들면 `anthropic_key.txt` 를 열어 **덮어쓰고 서버를 다시**
> 켭니다. 옛 키를 지우기 전에 새 키가 되는지 먼저 확인하세요.

### 14-5. 값

100만 토큰당 입력 $3 · 출력 $15 로 잡고 있습니다
(`app/domain/llm.py` 의 `PRICE_IN`·`PRICE_OUT`).
**요금표가 바뀌면 그 두 값을 함께 고쳐야 합니다** — 안 고치면 화면에 뜨는
값만 틀립니다.

회의 하나에 실제로 얼마가 들었는지는 **제안 칸 첫 줄에 함께 적힙니다.**

**본문이 안 바뀌면 다시 부르지 않습니다.** 오타 하나 고쳐 저장해도 앞의
결과를 그대로 씁니다.

### 14-6. 다른 방법 — 환경변수

파일 대신 환경변수로 줘도 됩니다. 서비스로 도는 앱은 파일 쪽이 간단해서
14-2 를 권합니다.

```
setx DCB_ANTHROPIC_KEY "sk-ant-여기에키"
```

넣고 나서 서버를 다시 켭니다. **환경변수가 있으면 파일보다 먼저 쓰입니다.**
