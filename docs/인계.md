# 대청부 수련회 시스템 — 미결 목록 (새 채팅이 먼저 읽는다)

갱신: 2026-09-27 **5단계 — 수입 화면이 섰다 (입금 캡처 읽기 포함 · 부분 닫힘)**.
사이드바 재정에 **예산과 지출 사이**로 「수입」(`/income`)이 붙었다. 담는 것이 둘이다 — **수입 항목**(7가지 종류 · 표는 예산 화면에서 옮겨 왔다)과 **회비·후원금 입금 내역**.
**쓰는 길은 안 늘렸다** — 수입 항목은 그대로 `/budget/incomes*` 가 쓰고 `/income` 화면이 그것을 부른다. 같은 표에 쓰는 길이 둘이 되면 갈린다.
**캡처를 읽는다** — 「📷 입금 내역 캡처 올리기」 → `llm.ask(images=…)` → 거래 줄. **출금(−) 줄은 빼고**, 읽은 것은 **전부 후원금 · 「추정」** 으로 담긴다(사람이 2026-09-27 에 정함). 겹침 열쇠는 **(시각 · 금액 · 잔액)** 이라 같은 캡처를 두 번 올려도 안 쌓인다.
**줄은 눌러 그 자리에서 편다**(팝업이 아니라 — 4-14 의 그 모양). 회비 금액은 **손으로** 적고(전액도 일부도), 저장하면 「추정」 이 풀린다. 필터 칩 넷(전체 · 회비만 · 후원금 포함 · 확인 필요).
**`llm.ask` 가 그림을 받는다 — 글만 보낼 때의 모양은 안 바뀌었다**(회의록 쪽 호출 그대로). **시험은 `httpx` 를 가짜로 바꿔** 나가는 몸통과 대답 읽기를 재고 **진짜 API 를 안 부른다**(11-3).
**화면 점검** — `docs/checks/fin.js` 에 수입 화면을 더했다(갈래 ⑰~⑳). 개발 서버 8001 · 375px 창에서 **관리자 12/12 · 부서 리더 4/4**(나머지는 총무팀만이라 건너뜀) · 실패 0 · 못쟀음 0 · 완주. 자가시험은 관리자 **잡음 4 · 놓침 0 · 못심음 16**, 부서 리더 **잡음 1 · 놓침 0 · 못심음 19**(셋은 그 계정에 자리가 없다 — 그것이 그쪽의 정답이다). 예산 12/12 · 지출 27/27 도 그대로 통과.

**부분 닫힘인 까닭은 하나다** — **개발 서버에 API 키가 없어 캡처 읽기를 실제로 눌러 보지 못했다**(봐둘것 **BK-b**). 키가 없을 때 그 사실을 화면이 말하는 것까지는 확인했고, 나머지는 pytest 가 가짜 `httpx` 로 잰다. 실제 은행 캡처를 모델이 얼마나 읽어 내는지는 **사람이 운영에서 한 장 올려 봐야** 안다.
