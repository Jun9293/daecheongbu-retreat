# 대청부 수련회 시스템 — 미결 목록 (새 채팅이 먼저 읽는다)

갱신: 2026-09-27 **5단계 마무리 — 잘못 읽힌 입금 줄을 고쳐 되살린다**.
캡처를 읽는 것은 사람이 아니라 모델이라 **이름이 잘못 읽힌다.** 그때까지는 그 줄을 취소할 수는 있어도 **바로잡을 길이 화면에 없었다** — 줄 편집에 **이름·금액 칸**을 뒀고 **취소된 줄에서도** 고친다.
**분류를 고치는 자리와 길을 나눴다** — 분류는 「이 돈이 무엇인가」 를 사람이 정하는 것이라 취소된 줄에서 막고(409), 이름·금액은 **「그때 무엇이 들어왔나」 를 바로잡는 것**이라 취소돼 있어도 고친다(`POST /income/deposits/{id}/fix`).
**고쳐도 겹침 열쇠는 안 움직인다** — 열쇠를 `dup_key` 에 **읽은 때의 값으로 얼렸다**. 안 얼리면 금액을 고치는 순간 같은 캡처가 다시 들어오고, 그것은 **취소의 뜻을 바꾸는 것**이다(사람이 「안 바꾼다」 로 정함). 칸은 **NULL 로** 붙고 옛 줄은 읽는 쪽이 셈한다(11-2 · `deposits.열쇠of`).
금액을 줄이면 회비 몫도 따라 줄고, **「추정」 은 안 풀린다** — 이름을 고친 것이 「회비인지 후원금인지 봤다」 는 뜻은 아니다.
**회비 금액 칸에 안내 한 줄**을 더했다 — 「비우면 전액 회비, 0 을 적으면 후원금 처리됩니다」. **막지 않는다**(사람이 정함): 0 도 사람이 보고 정한 값이고, 막으면 「전부 후원금」 을 적을 길이 없어진다.
**봐둘것 BK-c 를 닫았다** — ㄱ·ㄴ은 위의 둘이고 ㄷ(벽시계와 UTC)은 사람이 **이번에 안 고치기로** 정했다(재정 전체의 기존 구조 · 지금 그 값들을 견주는 코드가 없다).

**남은 단계는 없다 — 다섯이 다 섰고 5단계도 이 판으로 닫힌다.** 다음 판이 이어받는 것은 단계가 아니라 아래 표다. **다만 BK-b 는 열려 있다** — 개발에 API 키가 없어 **캡처 읽기를 실제로 눌러 본 적이 없다.** 사람이 운영에서 한 장 올려 봐야 「모델이 실제 은행 캡처를 얼마나 읽어 내는가」 를 안다.
